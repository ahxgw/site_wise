Context

Eporner is a free, ad-supported adult tube: user-uploaded and studio video, photo galleries, erotic stories, pornstar profiles, and an embedded cam surface. The domain was registered in April 2008. Its operator is unusually well documented for the category because a US appellate court had to identify him: in AMA Multimedia, LLC v. Wanat (9th Cir., 17 Aug 2020) the court described Marcin Wanat, a Polish citizen and resident, operating Eporner through MW Media, a Polish civil-law partnership, and affirmed he was not subject to US jurisdiction in a copyright suit. Revenue comes from advertising plus a Content Partner Program for verified uploaders. For a full-modal index it is the outlier of its category: alone among the large tubes it publishes a documented, keyless JSON API that pages through its entire video catalogue, ships Google video sitemaps with metadata inline, and publishes a sitemap of its own takedowns — then pairs that openness with an explicit contractual ban on mining any of it.

Retrieval Notes (site-specific deltas)

Only where eporner.com differs from the default platform assumptions.

Access track inverted

The default is a curated SEO sliver plus a metered API. Here the meter is absent and the API is the widest surface. Ranking the sitemap above the API — correct almost everywhere else — silently costs 57% of the catalogue.

Identifier & dedup

Two IDs coexist: the public base62 key in every URL and API record, and an internal numeric ID appearing only in thumbnail and imggen paths. Both are needed — base62 joins metadata, numeric is the only way to address image renditions. Slugs are SEO-mutable, and the same video resolves under four localised path segments across ten hostnames, all with canonical at www.

Quality signal, free

The operator publishes its own quality verdict as a query parameter, flagging three quarters of its catalogue low-quality. That is a labelled negative set most platforms never expose — usable as a ranking prior and as classifier training data before any of your own signals exist.

Deletion is a feed, not a discovery

Elsewhere deletions surface as unexplained 404 bursts. Here the removed set is enumerable up front and returns a correct 410 Gone, so tombstones load before the first crawl instead of being found by decay. The documented removed API method is broken; use the sitemaps.

Authoritative content field

JSON-LD is unusually complete, but its contentUrl is a decoy — the named mp4 403s. Trust the API record for metadata and JSON-LD for technical attributes. Treat keywords as one flat uncurated string mixing performers, acts and title fragments; split it against the 85K tag namespace before using it as facets.

Free-form renditions, thin edge

Unlike the signed transform CDNs on comparable tubes, imggen takes width, height and frame index unsigned and renders to 4K on demand — cheap for a visual index. But there is no CDN or WAF anywhere: bare nginx on rented metal, so nothing absorbs a burst. Crawl politely by choice, not because a challenge page forces it.

Search surface is doorway-heavy

172,909 pre-baked /search/{phrase}/ URLs are submitted as sitemap entries — SEO doorways, not content. Exclude them from the index but keep them as a query-intent vocabulary, which is a genuinely useful by-product.

Indexing Plan

How Site Wise would build the index for this site.

  • Retrieval unit: the video, keyed by base62 ID, carrying title, split keywords, duration, rating, view count, quality flag, uploader and 15 keyframes. Galleries are a second unit keyed by gallery ID; stories a third.
  • Primary keys & joins: base62 ID ↔ internal numeric ID (image addressing) ↔ pornstar slug ↔ tag slug. Perceptual hash over the 15 keyframes for cross-repost dedup, since the same clip appears under many titles.
  • Ingestion paths, ranked: 1) API search?query=all&per_page=1000, ~4,394 calls, no auth, ceiling = the whole video corpus; 2) videosDMCA*.xml first, to avoid indexing 173K tombstones; 3) video sitemaps for the view_count/publication_date fields the API omits; 4) photo/gallery sitemaps for the image corpus, which has no API; 5) page fetches only where comments are needed. No firehose, no bulk dump, no partner feed.
  • Recrawl cadence: order=latest page 1 daily catches the ~400/day of new uploads in a single call; DMCA sitemaps weekly; counts and ratings monthly on the HQ subset only; the low-quality 75% needs nothing beyond deletion checks.
  • Derivatives to generate: keyframe embeddings from the free 15-frame strip (the cheapest visual index in this category); ASR only on the 1.3M not-low-quality subset; keyword→tag normalisation. Skip OCR.
  • Demo to build: a corpus profiler that walks the wildcard API and cross-joins it against the DMCA sitemaps — measuring what fraction of a tube's advertised catalogue is already tombstoned, and how the operator's own quality flag distributes across upload years.

Risks to the Index

Only risks that change indexing strategy.

  • The openness is technical, not legal. Terms §3.4 reserves all TDM and AI-training rights under Art. 4(3) of Directive (EU) 2019/790 and bars automated extraction for those purposes without written consent; §6.2 bars framing or mirroring; §7.2 confines the embed player to personal non-commercial sites. An unauthenticated endpoint is not a licence — a commercial index needs consent, and the missing machine-readable opt-out is a defect in their reservation, not a permission.
  • API withdrawal is a single-config change. The whole plan rests on one endpoint with no published quota, which already ships a broken removed method and a deprecated v1. Key-gating or clamping the all wildcard would cut reachable coverage from 5.33M to 2.28M overnight. Keep the sitemap path warm.
  • Regulatory gates, not designation, are the threat. At a self-reported 15.8M EU recipients the site sits well under the 45M VLOP threshold, so no designated-platform transparency surface will appear soon — though its own figure is the only evidence. The nearer risk is age verification: UK and US state regimes push toward identity gates, and because everything here is reachable without a session, a region-scoped gate would do more damage to accessibility than any other single change.
  • Takedown-driven churn. 173K tombstones against 5.33M live records, on a site whose operator defeated US jurisdiction in a copyright suit, implies continuing DMCA pressure. Index on ID plus perceptual hash so re-uploads of removed material collapse onto one entity rather than fragmenting.

Open Questions

  • Photo-corpus size as objects rather than URLs — the census counts 899,827 /photo/ and /gallery/ URLs, but galleries hold many images each and there is no photo API. Would close by parsing a sample of gallery pages for image counts and extrapolating.
  • Registered-user and uploader counts — no operator figure found. Would close with a transparency report or enumeration of the /profile/ namespace, which robots.txt partly closes.
  • Whether the API has an undocumented rate limit — no 429, quota header or Retry-After appeared across roughly 1,200 requests in one session. Would close by ramping concurrency until a limit appears; deliberately not attempted.
  • Why /api/v2/video/removed/ returns an empty body — undocumented required parameter, or a silently broken method. Would close with a working parameter combination or an operator answer via contact@eporner.com.
  • What the 57% gap between the API's 5.33M and the sitemaps' 2.28M consists of — plausibly the low-quality tier withheld from search engines, but untested. Would close by sampling API IDs absent from the sitemaps and comparing their lq distribution against the corpus baseline.
  • Whether written consent for TDM is obtainable, and on what terms — §3.4 requires it and names no process or price. Would close by asking contact@eporner.com and recording the reply.
