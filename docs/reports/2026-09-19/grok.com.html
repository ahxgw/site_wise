Context

Grok is SpaceXAI's consumer AI assistant; grok.com is its web front door, alongside mobile apps, an X integration, and the xAI API. SpaceX acquired xAI in February 2026, listed on Nasdaq as SPCX on 2026-06-12, and rebranded the AI unit SpaceXAI in July 2026. Revenue comes from four Grok tiers, API access, data licensing, and X advertising.

For an index builder the site inverts the usual problem: there is almost nothing to crawl, because grok.com generates content on demand instead of hosting a corpus. Its one public object class is the shared conversation — a user-triggered permalink to a private chat, explicitly marked index, follow, whose body is withheld from crawlers. inferred The rebrand is unfinished in the site's own metadata, so name-based entity resolution will split. Basis: every page description reads "built by SpaceXAI" while the homepage JSON-LD creator node still names "xAI" (Probe Log).

Retrieval Notes (site-specific deltas)

Only where grok.com differs from the default platform assumptions.

Identifier & dedup

A share id is base64(prefix)_uuid4; the sampled prefix decodes to legacy-copy, so the namespace is already versioned. The hazard is on the page itself: two conflicting rel=canonical tags for one object, differing only in %3D versus =. Normalize percent-encoding before keying, or the conversation enters the index twice. There is also nothing to join on: no author, account, timestamp, model name or media reference appears on a share page, and the OG image is byte-identical across objects. Each conversation is an orphan record keyed only by its own URL — a flat corpus with zero graph structure, unusual for UGC at this scale.

Retrieval unit

The head of a shared conversation: a model-written title plus a 100-character prefix of the user's opening message. It inverts a normal document — the reliable summary is machine-authored, and the human-authored body is absent.

Authoritative content field

The <meta name="description"> is not a summary here, it is the only body text a non-rendering crawler gets; ranking on it means ranking 100 characters against a whole conversation. inferred The transcript is fetched client-side from an endpoint distinct from the public /rest routes. Basis: the RSC stream passes only {"shareLinkId":"…"}, the snippet phrase occurs in the payload solely inside meta tags, and six guessed /rest share routes returned 404 (Probe Log).

Freshness & recrawl

Both signals are broken: the sitemap has not regenerated in 369 days, and share pages carry no lastmod, date or Last-Modified under no-store. Recrawl can only run off the crawler's own last-seen clock. Deletion is the live risk, not staleness — a revoked share flips to a noindex stub under an unchanged 200.

Crawl policy: two layers that disagree

The advisory and enforced policies are different documents. robots.txt grants six named AI agents nine marketing paths before Disallow: /; the edge instead 403s GPTBot, ClaudeBot and CCBot — never named in the file — on those same allowed paths, while PerplexityBot, Google-Extended and Applebot-Extended pass (Verified Metrics). inferred The block is a Cloudflare-managed bot rule applied independently of the hand-written file. Basis: a 25-byte text/plain body with server: cloudflare and no app headers, firing on paths the site's own file allows and for a UA it never mentions. Read robots.txt as intent; test the edge for what works.

Quality & consent

The failure mode is not spam but non-consensual publication: private dialogue released by a button whose consequence users did not anticipate, with over 370K transcripts reaching Google's index in weeks (Verified Metrics). The directive that permitted it is still served 13 months later. Any index here holds material its authors did not knowingly publish, which no ranking signal fixes.

Indexing Plan

  • Retrieval unit: the shared conversation, keyed by the normalized /share/<id> URL, with title and snippet as the free tier and a rendered transcript as an optional, expensive upgrade.
  • Primary keys & joins: the normalized share URL is the only key — decode percent-encoding before hashing, per the double-canonical defect. No author, model or time key exists; do not design a schema that assumes one.
  • Ingestion paths, ranked: 1) Share URLs harvested off-site — the only route to the real corpus, cheap per object, coverage capped by what humans posted elsewhere. 2) Headless rendering of those URLs — the sole way to a transcript, at browser cost per object; reserve it for conversations already attracting links. 3) The metered API — licensed, but it generates content rather than retrieving the site's, so it is an enrichment budget, not a crawl budget. 4) The 7 marketing pages — index the JSON-LD entity once and never return. 5) grokipedia.com — for a SpaceXAI text corpus, 5.86M enumerable URLs sit one host away; grok.com is the wrong target for that goal.
  • Recrawl cadence: marketing pages quarterly, only to detect whether the 2025-09-15 sitemap ever regenerates. Share URLs need a liveness check, not a freshness check — poll for the noindex stub, since revocation rather than editing is what changes. Re-run the UA matrix monthly.
  • Derivatives to generate: the snippet is too short to embed usefully, so the high-value derivative is a consent and sensitivity classifier over harvested transcripts, flagging PII, credentials and medical content before anything reaches a servable index. Second, title-versus-snippet topic agreement — a free signal for whether a conversation is what its title claims.
  • Demo to build: a share-page evidence card — fetch a share URL and show the 100 characters a crawler sees, the byte-identical OG image, the index, follow directive and the two conflicting canonicals, beside the same object after headless rendering.

Risks to the Index

  • One meta tag deletes the corpus. The whole public surface depends on index, follow being served from share pages. It survived 13 months of privacy reporting, but the noindex stub for unavailable shares shows the restrictive template already ships — flipping it is a config change.
  • The licence cannot be verified programmatically. x.ai/legal/terms-of-service 403s every automated client tried (Probe Log), so the terms governing reuse are not machine-readable at all. An index built here rests on an unread contract — a legal exposure, not a technical gap.
  • The consent defect is unresolved and litigated. Transcripts were published by users who did not understand they were publishing, and grok.com is separately a defendant in a May 2026 wiretapping class action over its own tracking stack — whose Google and TikTok components are visible in the live CSP (Verified Metrics, Probe Log).
  • Edge enforcement is unstable and undocumented. The 403 set already diverges from robots.txt and includes a UA the file never names. Any crawler identity can be added silently, mid-crawl — build the fetcher to detect the 25-byte block body and fail loudly rather than record empty pages.
