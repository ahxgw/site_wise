fastdl.app

fastdl.app is a 233-page Instagram downloader on SaveFrom's backend that now sells Instagram scraping to AI agents as a paid MCP server.

Utility Downloader Ad-supported Paid Scraping API Zero Corpus

Evidence: verified inferred (must state basis) open — conventions in the methodology.

Context

fastdl.app takes a pasted Instagram link and returns the photo, video, reel, story or carousel as a file. Like ssstik.io it owns no corpus: 233 sitemap pages, all tool landing pages, and every media object belongs to Instagram and is fetched per request. Two things make it different from the rest of the downloader class. First, its client bundle carries SaveFrom.net's own namespace, upsell links and session-replay host, so it is a front end on the SaveFrom network rather than an independent tool. Second, since 2026 it sells the same extraction as a product: a contact-only REST API and a self-serve MCP server that offers AI agents Instagram profiles, comments, likers and follower lists at up to 1M requests a month. For an index builder this host is both a derivative-traffic case and a live example of unlicensed Instagram data packaged for agents.

Retrieval Notes (site-specific deltas)

Deltas from the default assumptions and from the downloader baseline set by ssstik.io.

Identifier & dedup

URLs are deliberately unstable. Each locale gets a random suffix (en5IW, de3Nu) that is reissued every few months, and the router 301s any digit-led near-miss to the current slug. An index keyed on URL accumulates dead aliases. Key the page on (function, locale) parsed from the path tail and the hreflang cluster instead.

Retrieval unit

The tool page, (function × locale): 9 functions × 25 locales. The /mcp and /api pages are a second unit class — product pages for a data service — and should be labeled as such, not merged with the downloader pages.

Cross-modal joins

The one join the site makes is the Instagram shortcode (DO5tIDME6t-) inside ?url= deep links. Those links are crawlable here (no Disallow) and canonicalize to the bare slug, so a crawler following them gets duplicate shells, and archives log user-pasted URLs. Collapse every ?url= variant onto its canonical; do not index the query string.

Authoritative content field

Title and H1 carry the intent. JSON-LD is unreliable: the rating sits on the terms page, and the terms text names a different brand (iGram). SpeakableSpecification is declared on every page, which suggests voice-answer targeting, not content structure.

Freshness & recrawl

No lastmod at all, and a 30-minute edge TTL. Change detection must come from slug changes: when the hreflang set in the sitemap changes, the whole site has been re-keyed.

Quality & spam

It has the downloader fingerprint (sitewide fabricated rating, competitor-brand pages fastdl-vs-snapinsta/indown/toolzu, near-duplicate locales) plus one new signal: URL-slug churn that keeps old paths alive as 301s.

Agent-facing surface

New for the category. The site advertises setup steps for ChatGPT developer mode, Claude connectors and Claude Code, and the MCP returns a payment link inside the chat. An agent-tool index or MCP registry crawler will meet this server. The 12 advertised tools (followers, likers, comments) are exactly what Instagram's terms prohibit collecting.

User query profile

Tool-seeking, mobile and South/Southeast-Asia heavy. The two estimators differ 2.4× on India's share (Verified Metrics), so treat any country weighting as unsettled.

Indexing Plan

  • Retrieval unit: the tool page (function × locale), 233 documents from one sitemap fetch, plus the /mcp and /api pages as a separate "data service" unit.
  • Primary keys & joins: synthetic key fastdl:{function}:{locale} from the path tail and hreflang cluster, with the current URL as a mutable attribute. Drop all ?url= variants. Link the host to the SaveFrom network entity, not to a standalone operator.
  • Ingestion paths, ranked: 1) Sitemap + open crawl (~233 fetches). 2) Weekly sitemap diff for slug rotation. 3) Nothing else: the resolver demands a signed body and CAPTCHA, and the MCP is a paid resale of data with no rights behind it.
  • Recrawl cadence: weekly sitemap hash; full refetch only when the hreflang set changes. Monthly existence check on f-d.app and the multitool.cloud hosts.
  • Derivatives to generate: a network-membership label. Fingerprint SaveFrom front ends by bundle markers: the sf.result response namespace, workerHubDomain/api-wh.* resolver hosts, utm_source=f0101xx SaveFrom/Televzr fallback links, and the multitool.cloud replay host.
  • Demo to build: a downloader-network mapper. Fetch each candidate host's JS bundle, extract those markers, and cluster hosts into operator networks. It would test whether fastdl.app, savefrom.net and siblings form one entity, and show how much of the "downloader" traffic class one operator controls.

Risks to the Index

  • URL rot by design. Five slug generations in ten months (Verified Metrics) means URL-keyed records, backlinks and cached snippets go stale on a schedule set by the operator.
  • Using the MCP as a source would import liability. It offers follower lists, likers and comments of third parties; that is personal data collected against Instagram's posted prohibition, and nothing on the site grants downstream rights.
  • inferred fastdl.app is a SaveFrom-network property, not an independent site. Basis: the unsigned resolver reply calls window.parent.sf.result, the bundle's error fallbacks link SaveFrom Helper extensions and savefrom.net/apk with SaveFrom-style utm_source=f0101xx codes, and the Televzr click-under is SaveFrom's cross-sell (Probe Log). Any enforcement action against SaveFrom (on USTR's 2025 Notorious Markets List) can take this host down with it.
  • inferred The operator is moving from ads to data resale. Basis: f-d.app (2026-01-27) and multitool.cloud (2026-03-09) were both registered this year, and multitool.cloud now hosts the MCP's OAuth server and the replay ingest (Probe Log). New infrastructure is going into the paid channel, not the downloader.
