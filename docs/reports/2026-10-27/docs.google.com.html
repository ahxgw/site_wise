Context

docs.google.com is where Google Docs, Sheets, Slides, Forms and Drawings run. The product grew out of Writely, which Google acquired on 2006-03-09 and relaunched on 2006-10-10. It is free for consumers and paid through Google Workspace seats for organizations. Unlike every other host in this series, it publishes no catalogue at all. The objects are private user files, and the public ones are public only because owners set sharing to "anyone with the link" or used "Publish to the web." Nobody announces those files: they surface when a school site, forum or form invitation links to them. For an index builder, this host is the largest open store of operational documents on the web: syllabi, handbooks, staff directories, schedules, sign-up forms, price lists. Every file has an anonymous plain-text, Markdown, CSV or PDF export. Google itself tells every crawler not to index any of it. Discovery depends entirely on outlinks from other sites, and indexing it runs against the host's own robots signal.

Retrieval Notes (site-specific deltas)

Only where this site differs from the default platform assumptions.

Crawl posture

This is a different pattern from the default two tracks. robots.txt allows the file paths to everyone with a 1s delay, but the response header forbids indexing, following links and snippets for every agent, including Googlebot, and there is no SEO sliver. Fetching is allowed; indexing is not. A compliant index can store a link and an owner-supplied title, but not the text.

Discovery

There is no sitemap, search or listing, and IDs are long random tokens, so the only discovery path is outlinks from other hosts. The reachable corpus equals the links an index already holds. Common Crawl's 62.7K distinct files per crawl is a floor set by its own crawl frontier.

Identifier & dedup

The native file ID is 44 characters; Office uploads have 33. Published pages use a separate opaque ID (2PACX-1v… for Docs/Sheets/Slides, 1FAIpQL… for Forms) that does not reveal the source file. The same file can appear as /edit, /view, /preview, /copy, /mobilebasic, /a/{domain}/… and ?usp= variants. Canonicalize to {type}/d/{id}, and key published pages separately.

Authoritative content field

Use the export output (Markdown for Docs, CSV for Sheets, text or PDF for Slides). Editor HTML is 0.2–2MB of app shell around an inlined model, and Common Crawl's language tags read that UI chrome (97.7% "eng" for Docs, while 3 of 12 sampled Docs were Russian or Italian). The title suffix "- Google Docs" must be stripped.

Freshness & recrawl

Files are mutable in place, and the URL never changes when content does. Loss shows up as 401 (sharing revoked) or 410 (deleted); both persisted in the recheck. Forms move from viewform to closedform rather than disappearing.

Quality & privacy

The public corpus is heavily institutional: schools, clubs and small organizations (class schedules, booklists, staff directories, membership forms). "Anyone with the link" is not consent to discovery, and sheets routinely expose names and emails. Forms are a known phishing vector: about 0.8% of Forms captures were already abuse-blocked.

Indexing Plan

  • Retrieval unit: a file (Doc, Sheet tab, deck, Form) keyed by type and ID, with Doc headings, Sheet rows and slides as sub-units. Index link metadata only (anchor text, linking page, title) unless the owner or linking site grants more.
  • Primary keys & joins: {type}/d/{id} ↔ published ID (no public mapping: open) ↔ linking page URL (the strongest context signal) ↔ og:image thumbnail. A Form joins to its response Sheet only through the owner.
  • Ingestion paths, ranked: 1) Drive/Docs/Sheets APIs with OAuth for files a user connects: full fidelity, quota-metered, consented. 2) Outlink seeds from the index's own web crawl, stored as link-only records (title from anchor text) that respect noindex. 3) Keyless export endpoints. They are technically open, but under the ToS clause their use for indexing needs legal review first.
  • Recrawl cadence: link records: check status (200, 401 or 410) monthly. Connected-account files: use Drive API change notifications instead of polling. Forms: weekly while open.
  • Derivatives to generate: for consented files only: Markdown and CSV normalisation, slide OCR from PDF export, a PII scan before any embedding.
  • Demo to build: a "public-link exposure" auditor: given a domain, list the docs.google.com links its own pages publish, with live status and a PII-pattern flag. This turns the census into a defensive tool rather than a scraper.

Risks to the Index

  • The header noindex, nofollow, nosnippet combined with the ToS ban on automated access "in violation of machine-readable instructions" makes full-text indexing of third-party files a policy breach, even though robots.txt allows fetching. This is the main constraint on the whole host.
  • Privacy exposure: link-shared files were never meant to be found. Indexing directories, rosters or form contents creates personal-data liability independent of Google's terms.
  • Google can tighten anonymous export (a signed-URL redirect is already in place) or remove the gviz and FB_PUBLIC_LOAD_DATA_ surfaces at any time. No documented contract covers them.

Inferences

  • 33-character IDs are Office files (.docx, .xlsx, .pptx) opened in the editors, and 44-character IDs are native files. Basis: 4 of the 5 sampled 33-character IDs had titles ending in .xlsx or .pptx; none of the 23 sampled 44-character IDs did.
  • The 21-digit number in the signed export path identifies the file owner, not the anonymous requester. Basis: it was identical for the txt and md exports of one Doc and for the txt and pdf exports of one deck, and it differed between the Doc, the Sheet and the deck, all requested in the same anonymous session.
  • noindex is applied to the whole host, not set per file by owners. Basis: 16 URL variants across 10 files (edit, preview, mobilebasic, pub, pubhtml, viewform, export, gviz) all returned the identical header, and the publish dialog in the help page offers no indexing option.

Open Questions

  • The total count of link-shared and published files. Closeable only by Google disclosure. A lower-bound proxy is the union of distinct IDs across several Common Crawl releases.
  • Whether published IDs (2PACX…, 1FAIpQL…) can be mapped to source file IDs. Closeable by publishing a test file from a Site Wise account and searching the published HTML and network responses for the source ID.
  • The rate limit on anonymous export endpoints. Closeable by a paced ramp on Site Wise-owned public files only, recording the first 429 or captcha.
  • How fast public files decay over months, not weeks. Closeable by rechecking the same 40-file sample on 2027-01-27 and comparing status counts.
  • Whether Google Search shows any docs.google.com results despite the header (for example, ones indexed before the header existed). Closeable by a sampled site:docs.google.com query set compared against fresh fetches.
