Context

Freepik was founded in Málaga in 2010 by Alejandro Sánchez, Pablo Blanes and Joaquín Cuenca as a freemium library of vectors, photos and PSDs. Free downloads require attribution, and a subscription removes that requirement. EQT bought a majority stake in 2020. Freepik then bought Videvo (2022), Iconfinder (2022), EyeEm out of bankruptcy (2023) and the Magnific AI upscaler (May 2024) (Wikipedia). On 2026-04-28 the whole company relaunched as Magnific, which put stock, image and video generation and upscaling under one brand. Video generation now brings in about half of revenue (Fortune). This matters for an index builder because the host in the traffic list is now a redirect shell. Every legacy freepik.com URL, image and API host resolves to a magnific.com twin. Stock is now a feature of an AI product rather than the product itself. The catalogue's metadata (AI-generated flag, licence, author, series) is rich, but it is only reachable through a keyed API.

Retrieval Notes (site-specific deltas)

Only where freepik.com differs from the default assumptions.

The traffic host is a redirect shell

Every probed freepik.com path that got past the filter, including robots, sitemap, images and docs, 301s to a same-path magnific.com twin. Freepik URLs live on in backlinks, attribution lines and older datasets, so key the index on the numeric asset ID, not the host. Store freepik.com URLs as aliases of the Magnific canonical.

The robots stance runs the other way

Most sites block AI crawlers by name. This one names none, and instead blocks its own AI-generated stock from every crawler, in 23 localized paths. Separately, every image response carries noimageai, a rendition-level opt-out. Read the two together: the company that generates 4M images a day keeps AI imagery out of web search and asks that its human-made previews not feed AI.

The sitemap index is readable, its children are not

The filter serves sitemap.xml but returns 403 for all 72 children, even to a single paced client. Robots also disallows /sitemaps/, a path the published index does not use. The sitemap shows the corpus's shape (27 families), not its size. A census needs the API's meta.total or archived child files.

Pagination caps force query slicing

page stops at 100, so no single query enumerates the catalogue. A census has to partition by period × content_type × license × color × orientation until each slice's meta.total falls below 100 × limit. Then sum the slices and check the result against the 250M claim.

Renditions are stripped, so provenance is external

The sampled previews have no EXIF, IPTC, XMP or C2PA data. Author, licence and the AI flag exist only in the API record. An image-first crawler, such as a reverse-image or perceptual-hash pipeline, gets anonymous pixels. Always join a rendition back to its API record before deciding whether it can be displayed or reused.

Stock is a side surface of a generation API

The developer docs list dozens of generation endpoints (Kling, Hailuo, WAN, Runway, Seedance, music, SFX) against 3 stock endpoints. Business pricing meters stock downloads in the same credits as generation. Expect the stock API to be maintained, but its quotas to be set for generation customers, not catalogue mirrors.

Indexing Plan

  • Retrieval unit: the asset, keyed by its numeric resource ID. The ID is shared by the …_{id}.htm detail URL and the API, and survives the host change. Child units are each format in available_formats and the preview rendition. Video assets get keyframes derived from the preview, not from source files.
  • Join keys: author.id → contributor; same_series and same_collection for set-level grouping; tags; the license PDF URL; the is_ai_generated and has_prompt flags. The legacy freepik.com URL is stored as an alias.
  • Ingestion paths, ranked: 1) The keyed /v1/resources, /v1/icons and /v1/videos list endpoints, sliced as described in Retrieval Notes, for the metadata census. 2) Detail calls for related and formats. 3) Preview renditions for embeddings, used only for display and retrieval, never for model training, given noimageai. 4) Archived sitemap children (Wayback/CC) to cross-check counts.
  • Recrawl cadence: daily order=recent&period=last-month sweeps for new assets. A monthly re-pull of detail records for licence and premium flips. A quarterly ID-panel recheck for removals.
  • Derivatives: CLIP-style embeddings from 626px previews; a style/series cluster from same_series; a separate partition for AI-generated assets, which their own robots.txt keeps out of web search; vector-format flags for SVG-capable retrieval.
  • Demo to build: an "alias resolver" that takes any freepik.com URL, image link or attribution string and returns the Magnific canonical, the licence PDF, the AI-generated flag and the series siblings. That covers the rebrand's broken-link and attribution gap.

Risks to the Index

  • inferred Akamai-class bot filtering decides crawl access per path. Basis: the block page's reference ID embeds the request's Unix time (1793757093 = 2026-11-04 01:51:33 UTC). That matches Akamai's reference-number layout, and the page has no server header. The index and robots passed while the children and HTML did not (Probe Log). Expect allowlisted search crawlers to see pages that research clients cannot, so do not plan around HTML.
  • The rebrand may move or collapse URL namespaces. The Probe Log shows same-path redirects only for robots, sitemap, docs and images, not for detail pages, which were 403 before any redirect. Keep alias tables and validate canonicals periodically.
  • EyeEm's photo corpus has an AI-licensing history. After the 2023 acquisition, EyeEm changed its terms so that uploaded photos could be licensed for AI training unless deleted within 30 days (TechCrunch, 2023-10-12). Any EyeEm-origin assets merged into the library may carry consent disputes; track their origin if the API exposes it.
