telegram.org

Context

Telegram is a messaging app with a broadcast product bolted onto it. The messaging half is private and structurally out of reach. The broadcast half — public channels and groups with @username handles — is a mass-media system that renders to the open web at t.me, and it is the only part an index can touch. The apex host telegram.org is marketing and documentation, core.telegram.org the developer surface, telegra.ph a long-form publishing sidecar. Money comes from Premium subscriptions, channel advertising, and Stars/Gifts on the TON blockchain, under a privately held BVI/Dubai structure. For an index builder the site is a paradox: technically it is one of the most openly crawlable large corpora on the web — no robots.txt, no auth wall, server-rendered archives back to 2015 — while its Content Licensing and AI Scraping Terms prohibit exactly the activity the markup invites. The wall here is contractual, not technical.

Retrieval Notes (site-specific deltas)

Only where Telegram departs from the default platform assumptions.

No robots.txt is not permission

The methodology assumes robots.txt names AI crawlers and marks the boundary. Across five hosts there is no file at all, so the Robots Exclusion Protocol is silent here — and the terms are not. The policy layer and the technical layer point in opposite directions, and only the policy layer binds.

Discovery, not access, is the ceiling

Every other large platform meters access and publishes a sitemap. Telegram inverts it: access is free and unmetered, but there is no sitemap, directory, enumeration API or way to list public channels, so coverage is a function of how many handles you can name. Worse, a public @username does not imply a public archive — t.me/s/NASA returned a bodiless 302 while four other handles each served 20 messages. Treat "has a handle" and "has a crawlable archive" as separate booleans and re-check the second, since an admin can withdraw it silently. inferred Handle discovery has to come from outside Telegram. Basis: /sitemap.xml is 404 on all four hosts, getPageList is Telegraph's only listing method and needs a token, and the archive view accepts only an exact handle (Probe Log).

An undocumented per-channel search endpoint

?q= on the archive URL runs full-text search over a channel's whole history and returns highlighted matches (Probe Log). It makes targeted retrieval cheap without a full crawl. inferred It is also the most fragile surface here. Basis: it appears in no documentation on core.telegram.org, so nothing constrains Telegram from changing or removing it, and no deprecation notice would be owed.

Authoritative content field, and the OG trap

There is no title/body split and no JSON-LD to disagree with — the message body is the whole object. But og:description holds the channel bio, repeated identically on every message page, so an indexer that trusts OG metadata stores the same description for all 460 posts in a channel. Take the message text node, never the meta tag.

Free live metrics, and missing tombstones

View counts, reaction tallies and subscriber counts sit in the HTML with no auth — signals most platforms hide behind a key. They make excellent ranking features and terrible facts, being monotonic counters read at an instant, so store them as (value, observed_at) pairs. Deletions, meanwhile, leave no marker at all. inferred Dense integer ids make deletion detectable where nothing else does. Basis: ids ran contiguously from 2 upward in the archive walk, so a missing id is a signal rather than noise (Probe Log).

Query profile is entity-first

Telegram's own Post Search — launched Jul 31 2025, scoped to public channels, gated behind Premium — reveals what users could not do before: search across channels. Off-platform the dominant intent is site:t.me <handle> navigation, because that is what external engines can serve. inferred Cross-channel topical search is the unmet need. Basis: Telegram built and monetised exactly that feature 12 years after launch, and it remains Premium-only.

Indexing Plan

How Site Wise would build this index — assuming the licensing question in Risks is resolved first, because it is not a formality here.

  • Retrieval unit: the message, keyed (channel_handle, message_id) — a natural atom, self-contained, individually addressable and embeddable at t.me/<chan>/<id>, carrying its own timestamp, view count and media. Telegraph articles are a second unit keyed by slug, joined wherever a message links one.
  • Primary keys & joins: the handle is the entity spine but is transferable, so resolve it once to the numeric internal id if a client path is available and treat the handle as an alias. Media joins by CDN path hash (stable across renders, unlike the signed token), which gives free cross-channel dedup of the forwarded images that dominate this corpus. Forward attribution joins a post back to its origin channel and is the only provenance signal on the surface.
  • Ingestion paths, ranked: 1) t.me/s/<handle>?before= archive walk — complete per channel, free, ~23 requests for a 460-message channel, and the only bulk path that exists. 2) ?q= per-channel search for targeted refresh without a full re-walk, accepting that it is undocumented and may vanish. 3) api.telegra.ph/getPage for linked long-form, which returns a clean node tree. 4) A registered MTProto client under the API Terms for anything the web view omits — but those terms carry the same AI/ML prohibition, so this path buys access, not rights. There is no fifth path: no dump, no firehose, no partner feed, and the Bot API is 401 without a token and blind outside its own chats.
  • Recrawl cadence: two loops. A one-request head-poll of page 1 per channel detects the newest id; only a moved id triggers a walk. A monthly integrity sweep re-reads older pages to catch edits and to read missing ids as deletions — enough for a back catalogue that is effectively frozen. Counters need their own cadence: sample views on a schedule if you want velocity, and stop treating them as attributes.
  • Derivatives to generate: ASR is the highest-value derivative and the one with no shortcut — nothing here carries a public transcript, and the modality mix skewed video-heavy on the page sampled. OCR matters more than usual, since a large share of channel content is screenshots of text. Skip thumbnails, which the CDN already serves sized, and skip alt-text extraction, of which there is none.
  • Demo to build: a channel-archive walker that takes a handle, pages back to id 1, and emits one JSONL record per message with id, timestamp, text, media hashes, view count and reaction tallies. It proves the claim the whole plan rests on — an 11-year archive in ~23 unauthenticated requests — and doubles as the deletion detector, since a complete id sequence makes gaps visible.

Risks to the Index

  • The terms prohibit the index, in the exact words. "Scraping, indexing, harvesting, aggregation" is a direct hit, and the AI/ML clause covers training, fine-tuning, validation, benchmarking and deployment. The only exception requires "explicit, informed, affirmative and continued consent" from every relevant user, per chat, non-transferable — which is not obtainable at corpus scale by design. Unlike the usual robots.txt negotiation, there is nothing here to comply with incrementally: the prohibition is categorical and there is no licensing programme to buy into. Any index built on this corpus is a legal decision made before a technical one.
  • Nothing machine-readable reflects that prohibition. No robots.txt, noindex, llms.txt or meta directive, so an automated compliance check reads the estate as fully permissive. Every crawler that respects only machine-readable policy is already non-compliant here and will not know it.
  • Both bulk surfaces are undocumented and therefore unowned. The archive view is an admin toggle, not a platform guarantee — one handle in five already returned a bodiless 302 — and a default flip would remove the only bulk path overnight with no deprecation window, because it was never published as an interface. The ?q= search endpoint is load-bearing for cheap refresh in the plan above and has no documentation, versioning or stability commitment at all. Build the full-walk fallback before depending on either.
  • Jurisdictional pressure is live and pointed at this exact surface. Telegram self-declares "significantly fewer than 45 million" EU monthly active recipients (Verified Metrics), keeping it below the DSA's very-large-platform threshold, and the founder was detained in France in Aug 2024 over platform content — an episode he was still writing about two years later (t.me/durov/544, Probe Log). inferred Regulatory outcomes will land on public channels first. Basis: the enforcement theory in both the French case and the DSA framing concerns publicly distributed content, which is exactly the layer this index would consume.
  • Provenance is weak where it matters most. Channels forward each other constantly and forward attribution is the only chain-of-custody signal in the markup. With no author identity beyond a transferable handle, a retrieved passage often cannot be traced to an origin — a citation-correctness problem with no technical fix on the public surface.

Open Questions

  • How many public channels exist, and how many expose the web archive? No directory, no enumeration endpoint, no sitemap. Closable only by an external handle corpus — harvesting t.me/ links from a general web crawl, then testing each for a 200 on /s/ — which measures reachability, never the true total.
  • How many total messages sit in the public-channel corpus? Per-channel maxima are readable from page 1, so a handle census would yield a defensible lower bound; without one, any figure is a guess.
  • Where is Telegram's rate limit on t.me/s/? Sixty requests at ~14 msg/s drew no throttling. Closable by a stepped-concurrency probe against the 429 boundary — necessary before scheduling any real ingest.
  • Do cdn*.telesco.pe tokens expire, and are large files range-limited? The path was stable across two renders minutes apart and a 7.4MB MP4 came down whole, but neither expiry nor a multi-gigabyte file was tested. Closable by re-requesting a captured URL at 1h/6h/24h and by fetching a large file with and without a Range header; the answer decides whether media URLs can be stored or must be re-derived at fetch time.
  • Does any commercial content licence exist? The terms describe no partner programme, paid tier or dataset. Closable only by a direct enquiry — and given the categorical wording, a negative answer is the likely one.
  • What is Telegram's current revenue and profitability? The $547M figure is self-reported for 2024 in a founder's channel post; bondholder disclosures are not public. Closable by a prospectus or an IPO filing, neither of which exists yet.
