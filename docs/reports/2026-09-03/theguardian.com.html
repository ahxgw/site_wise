Daily Site Profile

theguardian.com

The Guardian hands its entire 2.7M-item archive to a documented full-text API, then bans AI crawlers and prices training rights separately.

News Open API Reader-Funded RSL Licensing

Evidence: verified inferred (must state basis) open — conventions in the methodology.

Context

The Guardian is a British daily published since 1821 and owned through the Scott Trust, whose remit is perpetual editorial independence. It has no paywall: 1.3M recurring digital supporters fund open access for everyone else. That produces an index-builder anomaly. Most publishers meter the reading of their journalism; the Guardian meters the machine reuse of it. Its Open Platform Content API serves full body text and a deep tag taxonomy for essentially everything it has published, and a shared demo key returns all of it. Meanwhile robots.txt opens with a licensing notice, blocks 40 named AI and archival crawlers, and points at an RSL license.xml that permits ai-train only under paid subscription. inferred The Guardian has separated access from rights and sells only the second. Basis: the free developer tier documents "access to article text" for non-commercial use while the commercial tier names "training models for generative artificial intelligence services" as its priced case (see Verified Metrics), and license.xml attaches a payment URL to AI training rather than a prohibition.

Retrieval Notes (site-specific deltas)

Only where this site differs from the default platform assumptions.

Identifier & dedup

The CAPI id is the URL path — one key for the API row, the web page and the tag join, with no numeric ID to reconcile. The base-36 shortUrl (/p/x5qxd8) is the only alias, and it is the join key into comments. Editions are presentation, not namespace: all five fronts return 200 and x-gu-edition tracks the requester's geo, so articles need no per-edition dedup.

Retrieval unit

The article is the unit for 95% of the corpus, but liveblogs are the exception worth engineering for: one sampled liveblog held 107 separately timestamped blocks and 38.6KB of text under a single ID. Indexed whole, it buries the update the user is searching for. Split on block, retain the parent ID.

Cross-modal joins

All stable and free: id → tags → contributors; shortUrl → comment threads; mediaId → cross-item photo reuse. The broken join is media: video and audio return zero elements on the free tier, so text rows and media files cannot be linked without a commercial key.

Authoritative content field

Prefer CAPI bodyText over scraped HTML: it ships the editorial body without navigation, consent banners, or reader-contribution appeals. headline and webTitle diverge — the sampled liveblog had an SEO-shaped webTitle and a live-updated headline. Display headline, index both.

Freshness & date hygiene

Publishing peaked in 2006–2012 (849K items) and has fallen roughly a third since; the pre-web archive is negligible at 0.19%. Separately, order-by=oldest surfaces an item dated 0012-11-16 — a data-entry artifact. Date-sliced ingestion starting at the true minimum wastes slices on a millennium of empty range; clamp the lower bound to 1821.

Quality tiering

A single-publisher editorial corpus has no ranking-driven spam surface. Tier on the 41-value tone vocabulary instead — it separates news from comment, obituary, review and advertisement-feature, exactly the distinction retrieval needs and most news sites never expose. On comments, filter status: blocked tombstones.

Internal vs external search

Inverted from the norm: /search is Disallowed to crawlers, yet the CAPI q parameter gives any third party full-text search over the whole archive. The retrieval capability is more open than the crawl surface.

Indexing Plan

  • Retrieval unit: the content item keyed by CAPI id, with liveblogs exploded to body blocks carrying {parentId, blockId, blockPublishedAt}.
  • Primary keys & joins: id (canonical, = URL path) · shortUrl → Discussion API · tag IDs → contributor / series / section / tone facets · mediaId → image dedup.
  • Ingestion paths, ranked: 1) Commercial CAPI key — the only path clearing both the quota and the RSL licence, and the only one returning video and audio assets. 2) Developer key, evaluation only: 2.69M ÷ 200 per call = 13,445 calls minimum, or ~27 days of continuous polling at 500/day for a single pass. 3) Podcast and article RSS — unauthenticated, the cheapest freshness signal. 4) Discussion API for comments. 5) Public crawl, last: 534 sitemap URLs and a robots.txt that names most AI agents explicitly.
  • Recrawl cadence: liveblogs every 5 min while isLive; news RSS every 15 min; comment threads once at commentCloseDate + 1 day, then never; back catalog by lastModified sweep quarterly; tag vocabulary monthly.
  • Derivatives: ASR on the 12.2K audio items — no transcripts are published, so this is the largest missing text layer, and podcast MP3s are the one media class reachable without a commercial key. Skip OCR (all sampled images carry editorial altText and captions). Skip thumbnailing: i.guim.co.uk returns 401 on any unsigned resize, so derive from media.guim.co.uk origins or not at all.
  • Demo to build: block-level search over one day of type=liveblog items, shown against whole-document hits from the same corpus — the clearest demonstration that document granularity, not ranking, is what fails on live coverage.

Risks to the Index

  • The free tier is a demo, not a supply. The shared test key advertises 50,000 calls/day against a documented developer limit of 500 — a 100× gap with no terms behind it, revocable without notice.
  • RSL makes "we only read robots.txt" indefensible. license.xml permits AI training only under paid subscription and prohibits all other usage. Unlike a Disallow, it is a positive licensing offer, so ignoring it is a rights decision, not a crawl-policy one.
  • The crawler allowlist tracks who has signed. Its membership changes with commercial deals, not with policy — re-read robots.txt every crawl, never cache it.
  • The Discussion API is undocumented. 175.5M comments sit behind an unauthenticated endpoint absent from the Open Platform site, while /discussion/* is robots-disallowed on the web surface. That reads as an internal endpoint left reachable; treat its availability as temporary.
  • Wire photography is not the Guardian's to license. Image assets name third-party agencies in credit and source. A commercial key covers Guardian rights, not the supplier's, so reuse needs per-asset rights logic keyed on those fields.
  • The paging cap fails silently. A naive page-through stops at 1.4% of the corpus and returns HTTP 400, not an empty page — easy to log as a transient error and never notice.
