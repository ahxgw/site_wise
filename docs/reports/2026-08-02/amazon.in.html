Context

amazon.in is Amazon's India marketplace, operated by Amazon Seller Services Pvt Ltd. Indian FDI policy bars foreign-funded e-commerce from owning inventory for domestic sale, so amazon.in is structurally a pure marketplace: Amazon runs the catalog, ranking, logistics and ads, while title to the goods sits with third-party sellers. That constraint shapes the data — the offer layer is entirely third-party, and seller identity carries more weight than on amazon.com. The site runs its own ASIN namespace and, unlike the US store, publishes product content in eight languages. For an index builder the headline is access, not scale: the product detail pages, search results and browse pages that amazon.com answers with a bot wall are served on amazon.in to an ordinary HTTP client with no auth, no JavaScript and no cookie (Probe Log). inferred The two marketplaces run different bot-defense postures rather than one global policy. Basis: on 2026-08-02 the same client and user agent got HTTP 200 and 2.4MB from amazon.in/dp/B0BWYRH6QX and HTTP 404 from amazon.com/dp/B08N5WRWNW, a live US ASIN, on three consecutive runs.

Retrieval Notes (site-specific deltas)

Only where amazon.in differs from the default platform assumptions and from the amazon.com profile.

Identifier & dedup

The ASIN is still the key, but the namespace is India-only, so marketplace must be part of the primary key. The harder problem is locale: one ASIN exposes up to nine URLs, and each locale page declares its own rel=canonical with a translated, percent-encoded slug instead of pointing at a single canonical. Canonicalise on (marketplace, ASIN) parsed from the path, never on the declared canonical.

Retrieval unit

Product (ASIN) with language as an attribute of the document, not a separate document. Treating each locale page as its own record inflates the index eightfold with machine translations of one object.

Authoritative content field

English is the source text; the seven translations are machine output, and it shows — the sampled Hindi title renders "Self Adhesive" as a literal calque. Index translations for recall in Indic queries, but resolve entity and attribute extraction against the English page. Price, rating and review count are locale-invariant (₹249 / 4.3 / 572 across all nine variants), so they are safe to read from whichever page you fetched.

Crawl posture

The wall sits on the homepage, not the content: an ingestion design that probes / to test liveness will wrongly conclude the site is closed. Probe a detail page instead.

Cross-modal joins

Image URLs, offers, ratings and browse nodes all join on ASIN and are present in the crawlable HTML, so a text+image index can be built without API access. The video corpus does not join: Amazon MX Player content carries no ASIN and is not addressable from the retail pages.

Quality & spam

The FDI marketplace structure concentrates volume in a few large seller entities rather than Amazon itself, so the first-party/third-party split that carries trust signal on amazon.com is absent here. Machine-translated titles also degrade lexical spam detection: keyword stuffing survives translation, fluency heuristics do not.

Internal vs external search

Because detail and search pages are crawlable, external engines can hold a genuinely current copy of amazon.in text — the structural staleness noted for amazon.com does not apply to metadata here, only to price and stock.

User query profile

Expect code-mixed and transliterated queries (Latin-script Hindi) alongside native-script ones. Since only Hindi among the Indic trees is crawl-permitted, an index built from crawl alone will answer Tamil or Bengali queries with English documents.

Indexing Plan

  • Retrieval unit: product = (IN, ASIN), with a per-language title/description field set and offer + rating as fast-refresh sub-records.
  • Primary keys & joins: marketplace + ASIN parsed from the URL path; offer = ASIN + sellerId; image = CDN media ID. Do not trust the declared canonical.
  • Ingestion paths, ranked: 1) Unauthenticated crawl of the English tree — the only Amazon marketplace where this actually returns product data, seeded from /gp/bestsellers browse nodes and /s?k= (ceiling 50K results per query, 19 ASINs per page). 2) The /-/hi/ tree for Hindi text, the one Indic language robots.txt permits. 3) Creators API for offers, variations and browse nodes — gated on 10 qualifying sales / 30 days. 4) SP-API for sellers' own data. Review bodies and MX Player video: no legitimate path.
  • Recrawl cadence: price and availability daily at minimum (they are the only fast-churn fields in the crawlable set); titles and images weekly; browse-node tree monthly; treat the translated trees as derived and recrawl only when the English page changes.
  • Derivatives to generate: because there is no JSON-LD anywhere on the site, attribute extraction from DOM is mandatory rather than optional — budget for a parser and for it breaking. Then: transliteration index for code-mixed queries, and image embeddings for counterfeit/hijack detection.
  • Demo to build: a locale-diff harvester — fetch one ASIN across all nine locale paths, align the fields, and show which are translated, which fall back to English, and which are locale-invariant. It makes the "8 languages, 2 crawlable, 1 source of truth" problem concrete in a way a table does not.

Risks to the Index

  • PA-API 5.0 is deprecated. The locale-reference URL now 302s to a notice stating PA-API 5 "has been deprecated and is being replaced by the Creators API" (notice). No sunset date is published, so any pipeline built on the June 2026 amazon.com plan needs migrating on an unknown clock.
  • inferred The open crawl surface is the anomaly and should be treated as temporary. Basis: amazon.com serves a 404 bot wall on the identical path with the identical client (Probe Log), so the capability to close amazon.in exists and is already deployed elsewhere in the same company; the homepage WAF challenge shows it is partially deployed here.
  • The video corpus is mid-migration. Amazon declared Prime Video and MX Player unified on 2026-07-16 (Amazon Ads), yet /minitv still served the retired miniTV branding on 2026-08-02 with no redirect (Probe Log). Any video ingestion keyed to miniTV URLs will break without notice.
  • Regulatory ground is moving. DPIIT's Press Note 3 (2026 series), issued 2026-07-23, permits FDI in inventory-based e-commerce for exports of India-made goods while keeping the domestic B2C ban (Business Today). If Amazon takes first-party export inventory, a new first-party offer class appears in the data with different provenance from everything currently there.
  • inferred AI retrieval faces enforcement, not licensing, and the list is growing fast. Basis: 100 named agents sit at Disallow: / on 2026-08-02 versus ~30 on amazon.com on 2026-06-10, and the additions are agent-style UAs (Manus-User, Crawl4AI, Cloudflare-AutoRAG, GoogleAgent-Shopping) rather than classic training crawlers.

Inferences

  • amazon.in and amazon.com run different bot-defense postures rather than one global policy. Basis: identical client and user agent, same day, got 200/2.4MB from an amazon.in detail page and 404 from a live amazon.com ASIN, reproduced three times.
  • The open crawl surface should be treated as temporary. Basis: the closing capability is already deployed on amazon.com and partially deployed on amazon.in's own homepage.
  • AI retrieval faces enforcement rather than licensing here. Basis: 100 named agents at Disallow: /, weighted toward agent-style UAs, with no published AI licensing programme.
  • The seven non-English titles are machine translations of the English source rather than seller-authored copy. Basis: price, rating and review count are byte-identical across all nine locale variants of the sampled ASIN, while the title tracks the English string structure calque-for-calque.
