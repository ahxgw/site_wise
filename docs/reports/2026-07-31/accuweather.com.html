Context

AccuWeather is a privately held forecasting company that sells the same data three ways: metered APIs to 250+ Fortune 500 customers, advertising against its consumer properties, and subscriptions. It is the rare top-100 site with no user-generated corpus at all — every object is a machine-rendered view of a numerical forecast, valid for minutes to days and then replaced. That inverts the usual indexing problem: no back catalog to accumulate, no comment graph to mine, no revision history to diff, just a 3.5M-row location table joined to parameters that expire. The company defends the consumer site hard and sells the data separately — pages carry no JSON-LD, the Internet Archive is refused, and AI-crawler user agents have their connection dropped at the Akamai edge (Probe Log) — while the developer portal publishes llms.txt, llms-full.txt, and Markdown docs. A machine-readable sales surface bolted to a machine-hostile content surface.

Retrieval Notes (site-specific deltas)

Only where AccuWeather differs from the default platform assumptions.

Identifier & dedup

The location key is the whole identity system — a short integer (349727 New York, 347629 San Francisco) that every weather endpoint requires. URLs read /{lang}/{country}/{city}/{zip}/weather-forecast/{key}, but the ZIP is decorative: three NYC ZIPs all canonicalize to the same 10021 URL for key 349727 (Probe Log). Dedup on (language, location key, page type) and discard the ZIP and city slug. MinuteCast is the exception — it keys on raw lat/lon, so it will not join to a location key without a reverse lookup costing its own quota call.

Retrieval unit

Not the page. The useful unit is (location key, parameter, valid-time, issue-time) — a forecast assertion with two timestamps. Indexing the rendered page collapses issue-time, so you cannot tell a stale forecast from a revised one.

Freshness & recrawl

The inverted case the default assumptions do not cover: no back catalog, no revision history. Objects are replaced, not edited, and the previous value is gone unless you kept it. The API hands you the recrawl schedule directly via the Expires header, and the docs ask clients to randomize refresh times rather than align to the clock. Freshness here is a correctness property, not a ranking bonus — a two-hour-old "current conditions" record is wrong, not merely dated.

Authoritative content field

The API JSON is authoritative and the page text is a rendering of it, so the usual title-vs-body arbitration does not apply. The field to distrust is marketing breadth. inferred The advertised "200+ languages and dialects" counts language-region localizations, not languages. Basis: the same documentation table yields 214 localization codes against 56 language codes (Verified Metrics), and 214 is the only figure near 200+.

Quality & spam

With no UGC there is no spam surface and no manipulation incentive — a genuine absence, not a gap in measurement. The quality problem migrates to provenance: multiple providers publish contradictory forecasts for the same place and hour, so an index must retain which model issued a value and when, or it will silently blend competing predictions.

Policy lives at the edge, not in robots.txt

The two-track model holds, but the published policy no longer describes either track. inferred Enforcement has moved off robots.txt onto the Akamai edge, and unverified search-engine UAs are sinkholed rather than served. Basis: the 2026-02-01 robots.txt names no AI crawler, yet ClaudeBot and GPTBot UAs get their HTTP/2 stream killed while a Chrome UA gets a 403; and Googlebot/bingbot UAs from a confirmed US egress IP get reproducible 301s to m.weathercn.com, which serves a blanket Disallow: / (Probe Log). So a crawler obeying the published file learns nothing about what will happen, and a naive fetcher following the redirect indexes a different company's site.

User query profile

Nobody searches AccuWeather; users arrive at one location page from a search engine or open an app pinned to their coordinates. The query is always "this place, this time", never a topic — so relevance is entirely geo-resolution plus recency, and conventional text ranking contributes nothing.

Indexing Plan

  • Retrieval unit: the forecast assertion — (location key, parameter, valid-time, issue-time, unit system). Location records and article text are separate units with their own cadences.
  • Primary keys & joins: location key joins everything; (lat, lon) is the fallback key for MinuteCast; language code selects the localization variant. Persist the location table once and treat it as the dimension table for every fact stored.
  • Ingestion paths, ranked: 1) Core Weather API — the only complete path, but priced per call: indexing all 3.5M locations at any useful cadence exceeds even Elite's 2.4M calls/month and needs an enterprise contract. 2) Locations API sweep to materialize the location dimension once, then stop. 3) MinuteCast API for precipitation, separately metered. 4) Public crawl — unusable: 403 to browsers, stream reset to AI agents, no anonymous tier. 5) llms-full.txt for the docs corpus, which is genuinely open.
  • Recrawl cadence: drive it off the Expires header, never a fixed interval, and jitter as the docs request. Location dimension monthly, plus an event-driven refresh on NextOffsetChange so DST transitions don't corrupt local-time math. Article text daily. Ignore sitemap lastmod — it is ~9 months stale (Probe Log).
  • Derivatives to generate: forecast-skill scoring by retaining issue-time and grading each assertion against later observations; a ZIP-and-slug → location-key alias table built from canonical tags; unit normalization. Skip embeddings of forecast text — it is templated from the numbers, so the numbers are the better vector.
  • Demo to build: an Expires-driven quota planner — enter a location set and target staleness; it computes calls/month, names the cheapest sufficient tier, prices the CPM overage, and shows where budget forces wider staleness. Makes concrete the finding that this corpus is priced by freshness, not volume.

Risks to the Index

  • The reuse terms are unreadable, which is itself the risk. terms-of-use.md and brand-guidelines.md — the two documents defining what you may store and display — return unrendered component stubs, and /packages is 403 (Probe Log). Every License cell in the Access Matrix is open for this reason; no ingestion should start before the terms are obtained in writing.
  • Edge policy can change without any published signal. Because enforcement lives in Akamai rather than robots.txt, the posture can tighten between one crawl and the next with nothing to diff. Monitor by probing, not by watching the policy file.
  • Cost scales with freshness, not corpus size. The corpus is small, but every object expires. Any staleness target tighter than the tier allows converts directly into CPM overage — a design error in cadence is a billing error.
  • Self-serve tiers cap well below full coverage. Elite's 2.4M calls/month is under one call per location per month; full coverage requires an enterprise agreement whose terms and price are unpublished.
  • Archival recovery is closing. The Internet Archive has no successful capture of even robots.txt since 2026-02-01 (Probe Log). The archived sitemap and forecast pages this report relied on are being cut off — capture what you need from history now.
