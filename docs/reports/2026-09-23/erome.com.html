Context

EroMe is a free, ad-supported host where users upload albums of explicit photos and videos (up to 100 items per album, 2GB per file, per its FAQ) and share the links; Reddit is one of its three social logins. It pays no uploaders; verified "creators" instead get a bio link to their paysite under every album. The operator is not identified anywhere on the site: terms and DMCA pages name no company, the registrant is behind privacy, and the only named party is a US DMCA agent-for-hire. For a full-modal index it is the opposite of the open tubes: a Laravel app behind BunnyCDN with no sitemap, no JSON-LD, no feed and no API, whose browse surfaces all stop at page 50. Albums are keyed by random 8-character IDs, so the corpus cannot be enumerated — only discovered through links, profiles and search.

Retrieval Notes (site-specific deltas)

Only where erome.com differs from the default platform assumptions.

Neither track exists

The default is a curated SEO sliver plus a metered API. EroMe has neither: no sitemap for search engines and no API for anyone. Search engines see what any crawler sees — the site nonetheless gets about half its desktop traffic from organic search, so discovery rides inbound links rather than anything the operator submits.

Unenumerable keyspace

Album IDs are 8 random base62 characters (~2.2×1014 slots), so ID walking is hopeless, and unlike the tubes there is no wildcard listing. The numeric media sequence is dense but never appears in a URL — it measures the corpus without opening it.

A 5-hour horizon

With every listing capped at 1,800, /explore/new is a sliding window about five hours wide. A crawler that misses one window loses those albums from the global feed for good; they stay reachable only via profiles, hashtags or external links. Cadence is set by the cap, not by freshness needs.

Two kinds of "public"

Private albums leave listings and profiles but stay fetchable by URL, and the FAQ promises their uploaders "no search engine indexing". So an album URL found off-site (say, on Reddit) may be one the uploader asked to keep out of search. Before indexing an externally discovered album, check that it is listed — on the uploader's profile or in search.

Duplicate clusters by locale

Each album renders at www and 14 locale hosts, each with a self-referencing canonical, and the hreflang set points English, French and x-default at 401 dev hosts. Canonicalise on the album ID yourself and ignore the site's canonical and hreflang tags.

Root-level usernames

Profiles live at /{username}, so /api, /feed and /rss are someone's account. Classify URLs by path shape (/a/, /search, /explore, else profile) — never by probing well-known names, which return real 200s.

Indexing Plan

How Site Wise would build the index for this site.

  • Retrieval unit: the album, keyed by its 8-character ID, carrying title, hashtags, uploader, view count, and an ordered list of media items. Each item is a sub-unit keyed by its media key (plus numeric ID for videos), with dimensions, poster and type.
  • Primary keys & joins: album ID ↔ media key ↔ numeric media ID (video) ↔ username ↔ numeric user ID. Perceptual hashes on photos and video posters for cross-album and cross-site dedup: reposts are a first-class feature (profiles count them separately), and much content also lives on the paysites creators link to.
  • Ingestion paths, ranked: 1) /explore/new pages 1–50 polled every 3–4 hours — the only complete public feed, if the polling keeps up; 2) profile back catalogues for every uploader seen, the only route past the 1,800 cap into history; 3) hashtag search pivots from harvested tags; 4) external links (Reddit), admitted only after the listed-album check. No sitemap, API, dump or partner feed exists.
  • Recrawl cadence: set by the 5.1-hour window, not by change rate. Profile counters weekly for active uploaders; existing albums monthly for deletion (404) checks, as deletions are immediate and unannounced.
  • Derivatives to generate: image and poster embeddings (photos are unsigned and cheap); ASR only on videos in albums with meaningful views. Use media titles as captions where they differ from the album title.
  • Demo to build: a corpus estimator that reads the numeric media sequence and upload epochs from a small sample of the new-album feed and outputs creation rate, public-listing share and implied private/deleted fraction — measuring a closed corpus without crawling it.

Risks to the Index

Only risks that change indexing strategy.

  • Consent, not copyright, is the binding constraint. An anonymous-upload album host with Reddit login, a voluntary DMCA regime and fingerprint-based takedown is exposed to leaked paysite material and non-consensual intimate imagery. An index should honour private status (Retrieval Notes), propagate deletions fast, and keep a hash-based suppression list so removed material cannot resurface through reposts.
  • Silent terms are not permission. The terms grant the operator only the rights it needs to run the service and grant nothing to third parties. Absence of a scraping clause leaves copyright with each uploader; display beyond link-out and thumbnails needs rights review.
  • Brittle media addressing. The site warns URLs "can change at any time", video already requires an erome Referer, and one config change could extend that to photos. Store media keys and album IDs, not host-specific URLs; the s{N}/v{N} host number is not a stable part of identity.
  • Unaccountable operator. With no named entity or transparency report, there is no counterparty for a licence, a data agreement or a takedown escalation, and no regulator-facing disclosure to watch. Age-verification regimes could impose regional gates without notice; the only warning is the CDN's cdn-requestcountrycode header, which shows the edge already knows the visitor's country.

Inferences

  • Advertising is the primary revenue channel. Basis: Delegate-CH meta tags hand client hints to magsrv.com, pemsrv.com and tsyndicate.com; nav slots carry ad labels ("AI GF NUDES", "LIVE SEX"); the creators page says uploads are unpaid.
  • The numeric video ID is drawn from one global media sequence shared with other uploads. Basis: 11 videos in one album spanned 192 consecutive IDs, interleaved with photos that carry no numeric ID, and the sequence advanced at a near-constant ~128K/day across four anchors.
  • Most created media never appears in the public feed. Basis: ~8.4K public albums/day × 6.1 items per sampled album ≈ 51K items/day (calculated by Site Wise), against ~128K media IDs/day — the gap is consistent with private albums, 48-hour chat files and deletions, though the split is untested.
  • The two French-labelled hreflang targets are staging hosts leaking into production. Basis: dev.erome.com and devfr.erome.com both return 401 while every other locale host returns 200.
  • The thumbnail ?v= parameter is the upload time. Basis: it decodes to Unix times that fall in order along /explore/new pages and match the album's age in the rising media path bucket.

Open Questions

  • Live album and media counts — the 160.7M media ID and 18.0M user ID are ceilings, not counts. Would close by sampling a range of numeric IDs through any endpoint that resolves them (none found anonymously), or by counting albums across a large random set of profiles and scaling by user count.
  • Who operates EroMe — no entity on the site, privacy-protected WHOIS, and the D&B and French registry "Erome" entries matched a French commune name, not the site. Would close with a DMCA counter-notice record, a court filing, or payment-processor disclosures naming the operator.
  • Launch date — the domain dates to 1998, but the site's start is not established. Would close with the Wayback Machine CDX history for erome.com (the CDX API returned no parseable response on 2026-09-23).
  • Whether private albums are marked noindex or simply unlisted — every sampled (public) album was index,follow. Would close by fetching a known private album URL and reading its robots meta and headers.
  • Whether the profile pagination has its own ceiling — the sampled profile reached page 24 cleanly. Would close by paging a profile with more than 1,800 posts to page 51.
  • Rate limits — no 429 or challenge across about 70 requests at ~2/s. Would close by ramping concurrency on a listing endpoint; deliberately not attempted.
