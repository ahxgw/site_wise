Context

savefrom.net is a stream-ripping service: paste a YouTube, TikTok, Instagram, or Facebook URL and it returns a downloadable MP4 or MP3. It is not a corpus — it hosts almost no content of its own, and the media it delivers belongs to the source platform. Ownership is undisclosed, behind Tucows privacy redaction and Cloudflare. Revenue comes from advertising, the off-store SaveFrom.net Helper extension, a webmaster partner program, and a contact-only extraction API (Probe Log). USTR added it to the 2025 Notorious Markets List (Verified Metrics). It matters to an index builder for one reason, and it is not its content: the corpus Google holds and the page a US visitor loads are different documents, served from the same URL, discriminated purely by user-agent string (Probe Log).

Retrieval Notes (site-specific deltas)

Only where savefrom.net departs from the default platform assumptions.

The gate is inverted

The default assumption is that robots.txt blocks AI crawlers. Here that is inverted: ClaudeBot, GPTBot, and PerplexityBot receive the full page while an ordinary browser gets the 2,692-byte notice (Probe Log). AI crawlers are not merely tolerated, they are privileged over the site's own users.

No crawler verification

The allowlist keys on an unverified user-agent string — no reverse-DNS, no IP range check (Probe Log). inferred The purpose is SEO reach rather than partner access. Basis: the gate admits five unrelated commercial crawlers by name but rejects FooBot/1.0 and a Chrome string with bot appended (Probe Log), so it is a curated list of traffic-relevant crawlers, not a security control.

Retrieval unit

The page, and only the page. There is no sub-page object worth splitting out: no posts, no items, no records. A 593-URL corpus is a single small crawl, not an ingestion pipeline.

Authoritative content field

None of them. Title, description, JSON-LD, and body are all one authored marketing surface with no user or editorial layer to disagree with it. Where a normal site's SEO distortion sits on top of real content, here the SEO layer is the content.

Freshness & recrawl

Both freshness signals are synthetic: dateModified restamps to the fetch date on every request while the page is unchanged, and every sitemap lastmod shares one timestamp (Probe Log). An index that trusts either will recrawl a static corpus daily forever. Use content hashing instead.

Quality & spam

Treat the structured data as adversarial rather than descriptive: a VideoObject declared on a page whose embedUrl is itself and whose contentUrl is an 11-second UI clip, and an AggregateRating with no review objects behind it (Verified Metrics). Both are rich-result plays.

Internal vs external search

No on-site search exists; the input box is a URL extractor, not a query field. Discovery is entirely external, consistent with the 53.26% organic-search share (Verified Metrics).

User query profile

Navigational and how-to: "youtube to mp4", "ssyoutube", "tiktok mp3", "download instagram reels" — the sitemap is a direct transcript of the target query set, one page per head term.

Indexing Plan

  • Retrieval unit: the page. 593 URLs, no sub-objects, no media corpus.
  • Primary keys & joins: the numeric-prefixed slug (19-ssyoutube, 108-mp4-to-mp3) is the stable identity across all 18 language hosts; the host prefix is a language dimension, not identity. The trailing base-36 token in some paths (-6JL, -39IY) varies and should not be keyed on.
  • Ingestion paths, ranked: 1) sitemap crawl under an allowlisted crawler UA — complete coverage of the public corpus in one pass, but see the license conflict below. 2) Nothing else. There is no API for savefrom.net's own content; the advertised extraction API returns other platforms' media, which belongs in those platforms' index entries, not this one.
  • Recrawl cadence: monthly, keyed on content hash. Both native freshness signals are synthetic (Retrieval Notes), so honoring them would mean a daily recrawl of a corpus that does not change.
  • Derivatives to generate: none justified. The corpus is small, textually thin, and duplicated 18 ways; the localized variants deduplicate to the 50 canonical pages.
  • The actual recommendation: index the 50 canonical pages at low weight, but take the method as the deliverable. The UA-differential test used here is cheap, generalizes, and belongs in the crawl pipeline as a standing check: any large crawler-vs-browser divergence means the indexed document is not the document users receive.
  • Demo to build: a cloaking detector — for a seed list of hosts, fetch N URLs under matched crawler and browser user-agents from the same egress IP, and report byte-size ratio, visible-text ratio, and final-URL divergence. savefrom.net is the positive control at a 22:1 byte ratio.

Risks to the Index

  • Indexing it means republishing a document its own users cannot see. Any snippet, summary, or AI answer built from the crawled copy describes a service the clicking US user will not get — they land on the 2020 termination notice instead (Probe Log).
  • The crawl permission is self-contradictory. robots.txt grants Allow: / to everyone while the ToS forbids automated access entirely (Probe Log). A crawler cannot satisfy both, and the machine-readable one is the weaker instrument.
  • USTR listing is an active deindexing and blocking risk. Listing as a notorious market on 2026-03-03 (Verified Metrics) precedes search-engine demotion, payment-processor withdrawal, and national blocking orders; the same entry records service already terminated in the US, UK, and Spain.
  • Identity is designed to move. USTR names six related domains (Context). inferred The corpus should be keyed on content fingerprint rather than host, because the host is expected to change. Basis: six sibling domains under one operator plus the language-host naming already carrying migration scars — en1, pt1, it3 are numbered successors, not first-choice names (Probe Log sitemap census).
  • Structured data cannot be trusted as ground truth here. Ratings with no reviews and VideoObjects with no video (Verified Metrics) mean any pipeline that promotes JSON-LD to facts will ingest fabricated ones. This site is a reason to score markup credibility rather than parse it.
