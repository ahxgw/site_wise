Context

Scribd.com is the user-upload half of Scribd Inc.: hundreds of millions of PDFs, Word files, spreadsheets and scans that people uploaded to share or to unlock someone else's. Its sibling everand.com holds the licensed catalog and slideshare.net the presentations; one subscription spans all three. Distribution is search: a document page exists mainly to rank for phrases inside a file nobody else put on the open web. That makes the site unusually interesting to an index builder and unusually hostile to one. The retrieval object is a numeric document ID, and the ID is all that is normalized — path, slug and language subdomain are free variables that all answer HTTP 200 (Probe Log). The body text is complete and reachable, but it is served from an asset host whose robots.txt is Disallow: /, and on some documents it is run through a glyph substitution first. inferred Scribd deliberately ranks on text it does not let crawlers read. Basis: zero inline text_layer markup in 42/42 sampled document pages, every page's text delivered only as html.scribdassets.com JSONP, and that host banning all agents (Probe Log).

Retrieval Notes (site-specific deltas)

Only where Scribd differs from the default platform assumptions.

Identifier & dedup

The numeric ID is the only normalized component. Path (/doc/ vs /document/), slug and language subdomain are free, and every combination answers 200, not 301 (Probe Log) — so with 7 subdomains × 2 path forms × arbitrary slugs the alias space per document is unbounded. Key on the ID, verify against rel="canonical", and never treat the URL string as identity. The canonical is not always the www + /document/ form.

Retrieval unit

One record per document ID — title, author, page count, language, formats, thumbnail, any generated outline. A card, not a body. Page-level retrieval, which the positioned text layer would support beautifully, has no permitted ingestion path.

Cross-modal joins

Document ID joins the page, its thumbnail, its oEmbed record and its page assets. Uploader ID joins to /author/{id}/{slug} — but author there means the uploading account, not the work's author, which appears separately in the JSON-LD. On Everand the join key is the ISBN, connecting the catalog to every other bibliographic index; nothing comparable exists for user documents.

Authoritative content field

Title is uploader-supplied and often meaningless ("2" and "139-En" both appeared in the sample); JSON-LD name, OG title and the generated outline can all disagree. Where an outline exists it is the most descriptive field a crawler can get — and it is a model's summary of a file the crawler cannot read, so it inherits that model's errors unverifiably.

Freshness & recrawl

Sitemaps carry changefreq: weekly on every URL and <lastmod> on none, so the declared cadence is noise across 217M URLs. The working substitute is the timestamp inside the page's image_url, which matched Last-Modified 20/20 — but the sitemap overwrites that segment with its own build stamp, so it cannot be read from the sitemap. Change detection therefore costs one HEAD per document. Discovery is bounded by the nightly ~2h index rebuild (Verified Metrics).

Quality & spam

Upload-to-unlock earns free access by uploading, manufacturing a steady supply of re-uploaded copies of the same file under different IDs — and near-duplicate detection must run on thumbnails or generated outlines, since the text is unreachable. Provenance is uploader-only: exam papers, leaked manuals and pirated books share the URL shape of original work, with no rights signal in the markup.

Internal vs external search

Inverted from the usual platform: on-site search is robots-blocked (/search?, /documents/search) and the document-page surface exists to capture external search traffic. Users arrive from Google on a long-tail phrase and meet a login wall — show_archive_paywall: true on 42/42 sampled pages despite isAccessibleForFree: true in the same documents' JSON-LD.

User query profile

Verbatim-phrase queries: a sentence remembered from a syllabus, a form number, a manual's part number. It is the one intent the site is built for and the one an external index cannot serve, because the phrase being searched lives only in the layer nobody may crawl.

Indexing Plan

  • Retrieval unit: one record per document ID — JSON-LD fields, page count, formats, uploader, thumbnail, canonical URL, plus the generated outline/keyphrases when present. Body text is out of scope by policy, not by difficulty.
  • Primary keys & joins: scribd:doc:{id}, uploader scribd:user:{id}, Everand titles on ISBN. Canonical URL is an attribute, never the key.
  • Ingestion paths, ranked: 1) Sitemaps — complete ID enumeration, free, rebuilt nightly, no lastmod. 2) Document-page crawl — the only source of metadata and generated derivatives; at ~1.2MB each, transfer cost (~260TB for a full sweep), not rate limiting, is what forces selectivity. 3) oEmbed — cheap per-object refresh of title/author/thumbnail plus the sanctioned embed HTML; documents only. 4) Everand and SlideShare sitemaps — separate corpora. 5) Body text — no path; do not plan one.
  • Recrawl cadence: discovery from the nightly sitemap diff (new IDs only); change detection by HEAD on Last-Modified, prioritized by uploader activity and rating presence. Everand weekly — licensing churn moves titles in and out.
  • Derivatives to generate: thumbnail perceptual hashes for the re-upload duplicate clusters; language from JSON-LD inLanguage, not the sitemap bucket; an ISBN concordance for the Everand half.
  • Demo to build: a Scribd identity resolver — paste any URL form (/doc/, /document/, bare ID, wrong slug, any language subdomain), show that all answer 200, and collapse them to one ID plus the site's declared canonical.

Risks to the Index

  • The text layer is one robots.txt edit from legitimate, and one from gone. The whole indexable value of the site sits behind html.scribdassets.com's two-line file.
  • inferred Scrambling is expanding, not retreating. Basis: the platform ships an explicit per-document hasScrambledFonts flag, true on 3/42 sampled documents and on the one decoded in the Probe Log — the shape of a per-document rollout, not a legacy artifact.
  • AI-crawler policy is selective and unstable. Eight agents are banned outright while GPTBot, OAI-SearchBot, Google-Extended, PerplexityBot and Applebot-Extended go unnamed and therefore allowed (Probe Log). A list curated agent-by-agent will keep moving; re-read it every sweep rather than caching the stance.
  • Generated outlines are Scribd's editorial layer over other people's files. Indexing them republishes a model's description of a document that may itself be infringing, with no rights signal attached.
  • No API, no contract. oEmbed is the entire public interface and there is no developer portal (Probe Log), so it can be withdrawn without deprecating anything.

Inferences

  • Scribd ranks on text it does not let crawlers read. Basis: zero inline text_layer markup in 42/42 sampled pages, body text delivered only as html.scribdassets.com JSONP, and that host serving Disallow: /.
  • Font scrambling is an active per-document defence, not a PDF-extraction artifact. Basis: the state blob carries an explicit hasScrambledFonts boolean, true on 3/42 sampled documents, and the flagged document's page-1 text resolves under one monoalphabetic substitution to text matching its cover.
  • Sitemap language buckets are routing decisions, not document language. Basis: all nine indexes carry exactly 21,591 shards over the same ID ranges, and sampled JSON-LD inLanguage returned values (tl, zh, pt-br) with no bucket of their own.

Open Questions

  • Does Scribd server-render the body text inline for allowlisted search crawlers? vary: X-Bot says rendering is bot-dependent — closeable only from a verified Googlebot or GPTBot address, which Site Wise cannot originate.
  • Upload and deletion rate: sitemap-listed documents fill ~20% of the 1.0796B ID space, and whether the gap is deletions, private uploads or reserved ranges is unresolved. Closeable by re-running the shard census weekly and differencing the top shards.
  • What share of documents carry the generated outline/keyphrase layer, and what triggers it? 0/42 in a uniform sample versus its presence on a busier document suggests popularity-gating — closeable by sampling stratified on rating presence or recency.
  • Everand title counts — closeable with a 200-shard census by the method used here for documents.
  • Display rights for the generated outlines and keyphrases: nothing in the terms or markup says whether a third party may show them.
  • Whether the glyph substitution is per-document, per-font or global — closeable by comparing recovered maps across several flagged documents.
