Context

Game8 (ゲームエイト) publishes walkthrough "wikis" for mobile and console games. Each game gets its own slug (/genshin, /monst), and under it sit hundreds to thousands of numbered articles: tier lists, character pages, gacha evaluations and event guides. These are written by an in-house "攻略班" (strategy team), not by users. Readers add comments, Q&A and board posts. Revenue is advertising (the ads.txt is 49.7KB) plus a newer direct-payment store business. For an index builder, Game8 is a dense, entity-rich, Japanese-language reference corpus for game facts that publishers do not publish in structured form. Most of the facts sit in HTML tables of image icons, not in prose. Game8 is unusually easy to enumerate: one global article-ID space, a per-game sitemap that our probe found to be complete, and the same bytes served to every UA. Its owner calls game guides "AI-resistant" content, while robots.txt blocks training crawlers and lets AI search agents in.

Retrieval Notes (site-specific deltas)

Only where Game8 differs from the default platform assumptions.

Crawl policy is name-based and unenforced

The default assumption is that AI crawlers get blocked. Game8 splits them by purpose: 41 training UAs are blocked, while 11 search/user-fetch agents get the whole site except Tsum Tsum. With no * group, any crawler not named is unrestricted, including on the paths Googlebot is told to avoid. The server ignores UA entirely (identical bytes to GPTBot), so compliance is up to the crawler. A new crawler should adopt the Googlebot group's exclusions voluntarily, since they mark the low-value URL space (pagination, comments, search).

Identifier & dedup

The article ID is global and stable. /archives/{id} resolves any ID to its canonical game slug, and every sampled page self-canonicalizes, so dedup is trivial: key on the ID. The sitemap file number is the internal game ID (game_5 = Puzzle & Dragons), and image pages use the same ID (/720/images/… → /kh3/…). That gives a ready game-ID ↔ slug map.

Retrieval unit

The article is too coarse: one tier list holds dozens of entities. The useful unit is the table row (character / card / weapon × stats × rating), with its icon image. Article titles follow a fixed pattern, 【{game}】{entity}の評価とおすすめ…, so entity-page type is recoverable from the title alone. Text is Japanese, with game-specific romanization in slugs (pazudora, monst), so entity linking to English sources (wikis, game8.co) needs an alias table.

Cross-modal joins

Image IDs are global and appear in both <img> and data-image-url. Each icon sits in the table cell next to its entity name, which yields a large set of (Japanese entity name ↔ official game art) pairs. The JSON-LD image is the article's lead image only.

Freshness & recrawl

lastmod and dateModified are the same field, and both carry a bulk stamp. inferred Every article untouched since a November 2025 site-wide re-save was restamped 2025-11-20/21, so for those 228K URLs the date means "not edited since then", not "edited then". Basis: 53% of URLs share two consecutive days and no URL predates them, while sampled datePublished values go back to 2020. After the stamp, lastmod moves in step with editorial activity (~10.5K/day in October), so diffing the daily index is a cheap incremental feed.

Corpus follows the release calendar

The corpus tracks game launches and live-service events, not a back catalogue. Gunosy reported no major domestic title releases in FY2026, and growth came from overseas PVs (Verified Metrics). Expect new game_{n} files to appear as titles launch; detecting a new sitemap child is the "new game" signal.

Indexing Plan

  • Retrieval unit: article (keyed by global ID), split into table-row entity records with icon images; gacha banner page; game hub as the per-game ToC.
  • Primary keys & joins: article ID; game ID (sitemap file number) ↔ game slug; image ID; Q&A / board-post hex16 IDs; breadcrumb path for the article's place in the game's hierarchy.
  • Ingestion paths, ranked:
    1. Daily sitemap index (S3) → diff the 309 children's lastmod → fetch changed per-game files only. Full set 66.7MB; the census is complete.
    2. HTML fetch of changed articles (~10.5K/day). Respect the Googlebot-group exclusions and the /tsumtsum carve-out for AI-search use. Pages are 0.3–1MB, so the daily delta is about 4GB (calculated by Site Wise at ~400KB/page).
    3. Image fetch keyed by image ID, deduped globally; thumbnails (/thumb) for embeddings, not originals.
  • Recrawl cadence: active-game files daily by lastmod diff; gacha pages on creation; game hubs weekly; skip comments (noindex).
  • Derivatives to generate: table → structured entity rows (name, rarity, role, rating); a Japanese↔English entity alias table joined to game8.co; image embeddings for icon → entity lookup; per-game freshness profile from the lastmod series.
  • Demo to build: "screenshot → entity": embed the icon images from one game's tier lists, so that a user's screenshot of a character icon retrieves the Game8 row with its rating and the article it came from.

Risks to the Index

  • Most of the image layer is not Game8's to license: character art and screenshots belong to the game publishers. A display index can show thumbnails with a link; an image-model training use needs publisher rights, not Game8's.
  • Training is opted out: 41 named training UAs are disallowed site-wide. An index that feeds a model must use a search-agent identity and stay in that use, and must honour /tsumtsum.
  • Dates mislead: half the corpus carries a synthetic 2025-11 modification date in both sitemap and JSON-LD (Retrieval Notes). A freshness-ranked index would treat stale guides as recent.
  • Facts expire with patches: tier ratings change with each balance update, so the same URL can hold contradictory claims over time. Keep revision snapshots by lastmod, not only the latest version.
