Context

Threads is Meta's short-text conversation app, launched on 2023-07-05 and tied to Instagram accounts. Its web host moved from threads.net to threads.com; the old host now 301s to the new one (Probe Log). Meta says it has more than 500M monthly users and that it passed X on monthly actives, but gives no Threads revenue figure. Meta earns from ads across its apps. For an index builder, the logged-out web is a thin shell. Profile, post and tag pages return roughly 650KB of client app plus social-card meta tags, with no JSON-LD and no post bodies in the HTML. The robots.txt allowlists named search engines and social-preview bots and blocks everyone else, including all 17 sitemaps. Two things are open: the official oEmbed endpoint, which returns only a "View on Threads" card, and the post shortcode, which carries a decodable creation time. Compare instagram.com, which shares the Meta stack.

Retrieval Notes (site-specific deltas)

Identifier & dedup

Posts are keyed by an 11-character shortcode that decodes to a numeric ID whose high bits are a millisecond timestamp (Probe Log). Two URL forms name one post: /@user/post/{code} and the oEmbed permalink /t/{code}. Usernames can change, so key on the shortcode.

Retrieval unit

One post, with author, tag and time attached. A page carries one post's text only in og:description, which is truncated on long posts.

Cross-modal joins

Shortcode to creation time is stable and free. The avatar URL is signed and expires, so key it on username, not URL. The oEmbed permalink uses /t/{code}, which joins back to the post.

Authoritative content field

og:description for text and the shortcode for time; the <title> is just "Say more". The og:image is never post media.

Freshness & recrawl

Counters and tag volumes move continuously. Post text is mostly static once published. Deletion rate is open.

Quality & spam

The sitemap names (us_quality_tagged_tail, threads_high_potential_posts_v2, _tier_1…_tier_5) imply an internal quality score that gates what reaches search engines. inferred Basis: the tier and "quality" tokens in the 17 sitemap filenames in robots.txt.

Internal vs external search

/search?q=ai returns 200 with only a generic title and no canonical, so on-site search is not an indexable surface. External discovery runs through tag pages and the allowlisted sitemaps.

User query profile

The sitemap families include threads_question_posts, threads_tech_posts and threads_tags_gsc_bulk_keywords. inferred Basis: the "gsc_bulk_keywords" and "question" tokens in the sitemap filenames suggest Meta seeds pages from Google Search Console keyword data and targets question-style queries.

Indexing Plan

  • Retrieval unit: the post (shortcode), with username, tag list and decoded timestamp attached.
  • Primary keys & joins: shortcode (post and time), username (profile, mutable), tag name. Avatar and media URLs are signed and are never keys.
  • Ingestion paths, ranked: 1) the official keyword-search API, which needs a Meta app with threads_keyword_search approved and caps at 2,200 queries per 24h and 100 results per call (at most 220K posts per day, calculated by Site Wise). 2) A written-permission data agreement with Meta, which robots.txt names as the only route for automated collection. 3) Per-post page fetches for seed lists, limited to allowlisted UAs, so this is only available to an established search engine. No bulk path exists for a third party.
  • Recrawl cadence: tag volumes daily; profile counters weekly; post text once, then on deletion checks.
  • Derivatives to generate: time decoded from the shortcode; embeddings of og:description; ASR and OCR only for media obtained through the API.
  • Demo to build: a shortcode-to-timestamp decoder plus a timeline of a profile's posts from Wayback seed IDs. It needs no Threads request beyond the seed list.

Risks to the Index

  • Sitemaps, robots rules and the UA gate are all enforced by Meta's own edge, so an allowlist change closes the only crawl path without notice.
  • The API's stated display limit ("solely to the person who created it") conflicts with showing third-party posts in a search UI; confirm the current terms before building.
  • Meta can add post text to oEmbed or remove it from og:description at any time; neither is a documented contract.
  • The threads.net to threads.com move means old indexed URLs need 301 following and canonical remapping.
