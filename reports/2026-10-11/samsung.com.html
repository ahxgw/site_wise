Context

samsung.com is the consumer web presence of Samsung Electronics: one host, with a directory per country or language (/uk/, /be_fr/, /levant_ar/). Each directory combines a direct-to-consumer store, a B2B catalogue under /business/ and a support tree. For an index builder, it is a manufacturer's source of truth. Model codes are the spine, and the same code appears in product URLs, support URLs, review widgets, manual filenames and the product API. Samsung is also the most crawler-friendly big host in this series so far. robots.txt puts GPTBot, OAI-SearchBot, ChatGPT-User, PerplexityBot and Google-Extended in the same group as *, so AI crawlers get exactly the access everyone else has. Samsung also publishes llms.txt guides (Probe Log). The gaps are elsewhere: manuals sit on a separate host that disallows all crawlers, and the US site runs a different URL scheme that is barely sitemapped.

Retrieval Notes (site-specific deltas)

Only where Samsung differs from the default platform assumptions.

Identifier & dedup

The model code is the key everywhere. It is the uppercase path segment in support/model/, the lowercase trailing token in product slugs (…-sm-x946bzareub/, …-sku-qn77s85hdexza/), sku in JSON-LD, the Bazaarvoice productId and the Finder modelCode. Its suffix encodes colour, storage and region. Strip it to the base (SM-X946B) to group a device worldwide; the Finder modelName (SM-S741B/DS) does this already. Variant pages may canonicalize to a sibling (2 of 13 sampled pages), so dedup on canonical, then on the base code.

Retrieval unit

Index two units: the device family (Finder familyId), with its locale product pages and specs, and the support model page, with its manuals and help articles. Support outnumbers commerce about 12:1 in URLs (2.52M vs 208K product URLs, calculated by Site Wise). Most of the corpus is support for devices that are no longer sold.

Cross-modal joins

One model code joins page text, gallery images (p6pim/{site}/{modelcode}/), GLB/USDZ, manual PDFs (ModelName= in the download link), reviews and price. Across locales, sitemap hreflang clusters (up to 168 alternates) join translations. Use the sitemaps for this, not the HTML. No GTIN is exposed, so joins to retailer catalogues (Amazon, Walmart) must go through the model code in their titles or specs.

Authoritative content field

Samsung is the manufacturer, so its spec sheets and manuals outrank any retailer copy of the same facts. EU locales add regulated fields that retailers rarely carry: energy class, fiche and repairability index, each linked as a PDF from the Finder record.

Freshness & recrawl

Per-URL lastmod is real in the support, im, vd and da files (dates back to 2010) and is a generation stamp only in top_sitemap. All indexes regenerate daily (index lastmod 07:07 KST). inferred Support lastmod is bumped in bulk by template or firmware changes, not by manual edits. Basis: 24.8K UK support URLs (38%) share October 2026 dates, while pages like the 2014 Galaxy S5 support page are still listed.

Internal vs external search

/search/ and /ai-search/ are disallowed. The Finder API, which powers category listings, is the only structured view of the catalogue: family, model, price, rating and facets, with no key required.

Indexing Plan

  • Retrieval unit: device family (base model code), with child locale model codes; support model page and help article as separate records linked by code.
  • Primary keys & joins: full model code (SM-X946BZAREUB); base code (SM-X946B); Finder familyId; site code (uk, be_fr); Bazaarvoice productId = model code; manual CttFileID.
  • Ingestion paths, ranked:
    1. Sitemaps: 3.10M URLs and ~1.5GB of XML (calculated by Site Wise), regenerated daily. Diff per-URL lastmod to schedule fetches. Parse CDATA (Korea) and over-cap files whole.
    2. HTML crawl of product and support pages. robots.txt allows AI crawlers; pace it, since pages are 0.4–1.7MB each.
    3. Finder API per locale × category for family/model structure, price and ratings. It is undocumented, so treat it as fragile.
    4. Manual/regulatory PDFs: robots-blocked on the file host. Record the links and titles; fetch only with permission.
  • Recrawl cadence: price and stock daily via the Finder API for current models; product pages when lastmod changes; support pages weekly by lastmod diff; locale top pages and campaign pages (offer/, cdm/) can be dropped or crawled rarely.
  • Derivatives to generate: a base-code entity table (base code → locale codes → marketing names); ASR on product videos; manual text, if access is granted; image embeddings keyed by base code.
  • Demo to build: a "one device, every locale" card. Take one base code (e.g. SM-S741B), fan it out through the sitemap hreflang cluster and the Finder API in each locale, and show price, rating, energy label and support-page coverage side by side.

Risks to the Index

  • The document layer is robots-blocked: manuals, firmware and regulatory PDFs, the highest-value support content, sit behind downloadcenter.samsung.com's Disallow: / (Probe Log). A compliant index gets the support page but not the manual it links.
  • The US is a different site: 8.0K sitemapped URLs and no support/model pages, compared with up to 77K in other locales. US coverage needs HTML link discovery, not sitemaps.
  • Verified-bot gating: a spoofed Googlebot UA is refused while other UAs pass (Probe Log). inferred Akamai validates crawler identity, so a crawler claiming to be an allowed bot from an unverified IP can be blocked even where robots.txt allows it. Basis: 403 for the Googlebot UA alone, with identical 200s for GPTBot, ClaudeBot and curl from the same IP.
  • The Finder API is undocumented: its sibling card/detail endpoint already returns 403 to direct calls. Price and rating ingestion could close without notice.

Open Questions

  • Number of manual/firmware files. Closeable by extracting all downloadcenter links from a sample of ~1K support model pages and extrapolating per code, or from Common Crawl's copy of downloadcenter URLs.
  • Product families and models per locale from the Finder API. Needs the category type code list (from the site's category pages) and a sweep of totalRecord per locale × type.
  • Distinct base devices behind the 465.6K model codes. Closeable by normalizing codes per product line (strip colour/region suffixes) and deduping.
  • Whether US support model pages exist at scale outside the sitemaps. Closeable by crawling /us/support/ category trees and counting model links.
  • Review API access: whether a public Bazaarvoice passkey is embedded per locale, and what it allows. Closeable by inspecting a product page's network calls in a browser.
  • samsung.com traffic split by locale and by store vs support. Needs a third-party panel (Similarweb) or Samsung disclosure; not available here.
