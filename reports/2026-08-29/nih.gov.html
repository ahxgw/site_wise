Context

NIH is the U.S. government's medical research agency, funded by a $47.2B FY2026 appropriation across 27 institutes and centers. For an index builder the agency's public-affairs site is nearly irrelevant; what matters is the National Library of Medicine subtree on ncbi.nlm.nih.gov, which operates PubMed, PubMed Central and 36 Entrez databases holding billions of sequence and variant records. This is the inverted case among high-traffic sites: no ad model, no engagement ranking, no revenue meter on access. The corpus is a U.S. government work distributed under terms requiring attribution but not permission, and NIH publishes bulk dumps of its own catalog. The binding constraints are structural rather than commercial — a migration of PMC bulk distribution off FTP onto AWS that completed within the last four days (Probe Log), and a widening gap between an HTML surface hardening against automation and an API surface that remains completely open.

Retrieval Notes (site-specific deltas)

Only where nih.gov departs from the default platform assumptions.

The AI-crawler default is inverted

The methodology assumes robots.txt blocks GPTBot, ClaudeBot and peers. NCBI names none of them across 390 lines, and PMC explicitly allows /articles/ to User-agent: *. inferred The omission is policy, not oversight. Basis: the same file actively curates per-agent blocks for ten named crawlers including obscure ones (yacybot, Browsershots), and PMC's allowlist was rewritten for the new host without adding AI agents.

No revenue meter

The default two-track model — SEO sliver plus revenue-metered API — does not apply. No paid tier, no sales requirement, no partner agreement. The only throttle is a 3 req/s courtesy limit a free key lifts to 10. Access is bounded by politeness, not price.

HTML hardens while the API stays open

PubMed record pages return HTTP 203 with a cookie challenge and no metadata; www.nih.gov 403s every non-browser client. Meanwhile efetch serves the same record as 29.7KB of unauthenticated XML. inferred The challenge shapes transport rather than withholding data. Basis: the identical record is served in richer form over the open API from the same organization on the same day (Probe Log).

Do not trust PubMed's sitemap

PubMed advertises a sitemap in robots.txt that resolves to an empty index. A crawler treating sitemaps as the coverage plan would conclude PubMed has zero indexable URLs. PMC's index is real (1,352 children); PubMed's is a stub, and bulk FTP is the intended path.

Identifiers are unusually clean

PMID, PMCID, DOI and MID are stable, curated, and cross-walked by NIH itself in a 253MB CSV refreshed daily. Article versioning is explicit in the S3 key (PMC10000000.1), so supersession is detectable without diffing content.

Quality signal replaces spam signal

With no engagement ranking to game, the usual manipulation surface is absent. The analogous risk is scientific: retracted and corrected articles remain live and citable. The is_retracted flag and CommentsCorrections elements are the trust signals to carry into the index.

Internal search is the query workhorse

PubMed's field-tagged syntax ([dp], [sb], [filter], MeSH explosion) expresses queries a general web index cannot — every count in Verified Metrics came through it. Users want Boolean recall over a controlled vocabulary, not ranked relevance. Records are also near-immutable once indexed, so churn is append-only rather than editorial.

Indexing Plan

How Site Wise would build this index.

  • Retrieval unit: the article, at two granularities — the PubMed citation (title + abstract + MeSH, 41.08M units, complete coverage) and the PMC full text section (8.19M articles chunked by JATS <sec>, for passage retrieval).
  • Primary keys & joins: PMID as the spine; PMCID (versioned) for full text; DOI for external joins; MID for author manuscripts. Load PMC-ids.csv.gz once as the crosswalk table rather than resolving identifiers per record. MeSH descriptor IDs join citations to the 355.8K-term controlled vocabulary; RePORTER core_project_num joins publications to the funding graph.
  • Ingestion paths, ranked: 1) PubMed FTP baseline + daily update files — complete metadata coverage, no auth, no rate limit, one annual full rebuild. 2) The pmc-oa-opendata S3 bucket for full text, figures and PDFs — unauthenticated, checksummed, version-keyed, ceiling 8.19M articles. 3) E-utilities for reconciliation and for the 28 non-literature Entrez databases — 10 req/s keyed, so reserve it for deltas rather than backfill. 4) RePORTER API for the grants layer. 5) Browser-equivalent rendering for www.nih.gov only, and only if agency prose is worth the cost — it is a rounding error against 41M citations.
  • Recrawl cadence: daily for PubMed update files and the S3 inventory; weekly for RePORTER by date_added; annually for the baseline rebuild; on-publication for retraction sweeps. Sequence databases refresh nightly upstream, so pull only the identifiers actually referenced.
  • Derivatives to generate: embeddings over title+abstract for all 41.08M citations and over full-text sections for the 8.19M OA articles; figure-caption pairs from JATS for cross-modal image retrieval (captions are already structured — no OCR needed); OCR only for the historical-OCR subset, where the scans are the primary artifact. Skip ASR entirely.
  • Demo to build: a retraction-aware citation lookup — resolve any PMID/PMCID/DOI through the crosswalk, return the abstract from efetch, and surface the is_retracted flag and CommentsCorrections links alongside it. It exercises the join table, both open paths, and the one quality signal that actually matters here.

Risks to the Index

  • The PMC bulk migration is live right now. Legacy FTP datasets and the OA Web Service API were removed within days of this report (readme dated Aug 25 2026; all bulk paths 404 on Aug 29). Any pipeline pointed at ftp.ncbi.nlm.nih.gov/pub/pmc/oa_bulk/ is already broken. The replacement drops compressed packages entirely for per-article objects, turning ingestion from "fetch N archives" into "enumerate 8.19M prefixes" — a cost profile that needs the daily inventory CSV to stay tractable.
  • The 203 challenge may spread. PubMed record HTML went from crawlable to cookie-gated; www.nih.gov is fully Cloudflare-walled. If the same treatment reaches PMC article HTML, the 4.37M non-OA full texts (calculated by Site Wise: 12.56M less 8.19M) lose their only access path, being absent from the S3 bucket by definition.
  • Appropriation risk is index risk. This corpus has no revenue backstop; distribution infrastructure is a budget line. A funding disruption degrades bulk services rather than the underlying data.
  • License heterogeneity inside the OA Subset. "Open Access" is not one license — per-article license_code ranges from CC0 to non-commercial terms, so treating the subset as uniformly redistributable is a licensing error at 8.19M-article scale. The COVID-19 collection is the precedent: publishers retroactively pulled articles from bulk distribution when emergency terms expired, and NLM published removal lists for downstream correction.
  • Official statistics lag the live corpus. NLM's published production statistics are three years stale. Any figure taken from documentation rather than the API will be wrong by millions of records.

Open Questions

  • What is the license split inside the 8.19M-article OA Subset? Entrez license filters returned zero, so the breakdown needs a full pass over the license_code field in the S3 per-article JSON sidecars.
  • Where is the daily CSV inventory documented for the OA bucket? The cloud-service page describes a 30-day-retained daily inventory, but no inventory/ or _inventory/ prefix was listable; closing this requires the AWS access documentation or a support query, and it determines whether incremental ingestion is cheap or requires full re-enumeration.
  • How many figures and media objects exist across the OA Subset? Closable by summing media_urls lengths across the per-article JSON during the first full ingest.
  • What is nih.gov's actual traffic and its split between www.nih.gov and the NCBI subtree? No official analytics are published; a federal Digital Analytics Program export or a named third-party estimator would close it.
  • Is www.nih.gov Cloudflare policy configured to admit declared search crawlers? The 403 was observed from a residential path with two user agents; verifying requires a reverse-DNS-verifiable Googlebot request or the agency's own statement.
