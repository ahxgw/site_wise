live.com

live.com is a 301 to Outlook.com: no robots.txt, no public page; mailboxes open only through delegated Microsoft Graph OAuth.

Webmail Auth-Walled Microsoft Graph Exchange Online Zero-Crawl

Evidence: verified inferred (must state basis) open — conventions in the methodology.

Context

live.com is the legacy domain of Microsoft's consumer mail and identity stack. Hotmail launched Jul 4 1996, Microsoft bought it in 1997, and Outlook.com replaced it in public preview on Jul 31 2012; today live.com, hotmail.com and outlook.com all 301 into the same Outlook web app, while login.live.com remains the Microsoft account sign-in page (Probe Log). Revenue is inbox advertising plus Microsoft 365 Consumer subscriptions, which Microsoft's FY2026 10-K ties directly to "demand for communication and storage through Outlook.com and OneDrive". For an index builder this host is a sibling of mail.yahoo.com and mail.google.com: a giant private corpus with zero public surface. The delta is the access path. Consumer mailboxes run on the same Exchange Online fleet as business tenants, so they inherit its protocols (Graph, EWS, ActiveSync, IMAP) and its deprecation schedule. Microsoft has retired Basic auth, the Outlook REST API, and now EWS in two years, leaving Graph as the only durable path.

Retrieval Notes (site-specific deltas)

Only where Outlook.com departs from the default platform assumptions and from the Yahoo/Gmail webmail reports.

Identifier & dedup

Graph's default message id changes when the item moves folders. Send Prefer: IdType="ImmutableId" on every request, including delta and subscriptions, to get an ID that survives folder moves and changes only on archive or export/re-import. translateExchangeIds converts up to 1,000 legacy IDs per call. Key on accountId + immutableId. Use internetMessageId for cross-provider dedup.

Retrieval unit

Index the message, present the thread, and promote each attachment to its own document, as on Yahoo. One addition: uniqueBody gives the reply without quoted history. Index uniqueBody for recall and keep body for display, so a 30-message thread is not indexed 30 times over.

Cross-modal joins

Stable: immutable message ID → attachment ID → bytes; conversationId → messages. Microsoft adds a join that IMAP providers lack: OneDrive "attachments" are links into a second Graph resource (Files) under the same identity, so the mail and file indexes share one user id and one consent screen.

Authoritative content field

Do not trust the sender address on its own. With DMARC p=none on outlook.com, hotmail.com and live.com (Probe Log), spoofed mail claiming those domains is not rejected by policy. Index the Authentication-Results line from internetMessageHeaders as a trust feature, not the From line.

Freshness & recrawl

This is the inverse of Yahoo. IMAP here also lacks CONDSTORE/QRESYNC, but Graph has per-folder delta with opaque tokens, documented for personal accounts at Mail.ReadBasic. Incremental sync is cheap on Graph and expensive on IMAP, so IMAP should not be used for anything except fallback.

Quality & spam

Every message exposes inferenceClassification (focused / other), Microsoft's own relevance label, which the user can correct. It is a free per-message priority prior that IMAP providers do not expose; use it as a ranking feature, not a filter.

Internal vs external search

The anonymous autodiscover list names SubstrateSearchService and OutlookCopilotMailIntelligenceService (Probe Log): Microsoft's own mail retrieval runs on the Substrate index behind Copilot, which is not offered to third parties. Graph $search on messages is the only public query interface.

Indexing Plan

  • Retrieval unit: message (indexed on uniqueBody), thread for presentation, each attachment a sibling document.
  • Primary keys & joins: consumers-tenant user id + Graph immutable ID; conversationId groups; internetMessageId dedups across providers; OneDrive item IDs join linked attachments.
  • Ingestion paths, ranked: 1) Microsoft Graph delegated (Mail.Read + offline_access), with an app registered for personal accounts. It is the only path with delta sync and immutable IDs; ceiling 10K requests per 10 min per mailbox. 2) Graph contacts/calendar/To Do under the same consent. 3) IMAP XOAUTH2: fallback only, no delta and no stable cross-folder ID pre-auth. 4) EWS and EAS: do not build. EWS is in phased shutdown on Exchange Online, and EAS is a device-sync protocol. 5) Public crawl: nothing exists.
  • Recrawl cadence: Graph delta per folder every few minutes on Inbox and Sent, hourly on others; contacts/calendar daily. The 15 GB free cap and over-quota bounce (Verified Metrics) mean storage-pressure deletions show up as delta removals and must be honored.
  • Derivatives to generate: attachment text extraction and OCR; thread summaries over uniqueBody chains; sender-trust features from Authentication-Results.
  • Demo to build: on a mailbox the operator owns, sync one folder twice, once with default IDs and once with ImmutableId, then move 100 messages and measure how many default IDs break. Then compare indexed bytes between body and uniqueBody across long threads.

Risks to the Index

  • Protocol churn is Microsoft's pattern here. Outlook REST v2.0 was decommissioned Mar 31 2024, Basic auth for Outlook.com ended Sep 16 2024, and EWS on Exchange Online began phased disablement on Oct 1 2026 (Verified Metrics). Anything not on Graph has a published end date or is likely to get one.
  • inferred Business-tenant changes reach consumer mailboxes. Basis: IMAP on imap-mail.outlook.com and outlook.office365.com returns byte-identical capabilities from *.PROD.OUTLOOK.COM backends; SMTP answers as *.outlook.office365.com; and OWA headers carry the same x-calculatedbetarget naming (Probe Log). Exchange Online throttling and deprecations should be assumed to apply here until shown otherwise.
  • inferred Discovery documents advertise dead paths. Basis: anonymous autodiscover still maps Rest to outlook.office.com/api two and a half years after v2.0 was decommissioned, and POP still advertises USER/PLAIN after the Basic auth cutoff (Probe Log). A client that configures itself from autodiscover or CAPA alone will select endpoints that fail.
  • Scale is getting less visible. Microsoft dropped the consumer subscriber count from its FY2026 10-K (Verified Metrics), removing the last official scale figure for this corpus.

Inferences

  • Consumer Outlook.com mailboxes are Exchange Online mailboxes. Basis: identical IMAP capability strings and *.PROD.OUTLOOK.COM backend names on the consumer and Microsoft 365 IMAP hosts, SMTP greeting from *.outlook.office365.com, and x-calculatedbetarget backend headers on /owa/ (2026-10-28).
  • Discovery metadata lags deprecations. Basis: autodiscover Rest → outlook.office.com/api and POP CAPA USER/SASL PLAIN observed 2026-10-28, against the Mar 31 2024 REST and Sep 16 2024 Basic auth retirements.
  • The 417 on /mail/ is a client-type gate rather than an outage. Basis: the same request returned 0 bytes with x-backendhttpstatus: 417,417 from a named backend, while /owa/ on the same host answered a normal 401 AuthError (2026-10-28).
