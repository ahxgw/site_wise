Context

The Internet Archive is a San Francisco nonprofit that runs the Wayback Machine and a general-purpose digital library of books, video, audio, software, images and datasets. Its robots.txt blocks only two admin paths and lists one sitemap; the site is the most open large corpus Site Wise has probed. Uploads come from the public, libraries and its own crawls and digitization lines, so rights vary per item. Funding is donations and grants plus program revenue, per its Form 990. For an index builder the unusual fact is the split: a keyless search API enumerates all 129.6M items with rich fields, but roughly a third of the items sit behind lending or access restrictions, so the file layer is much smaller than the catalogue. The Wayback Machine is a separate corpus of captured web pages with its own index (CDX) and a tightening rate limit.

Retrieval Notes (site-specific deltas)

Identifier & dedup

identifier is the stable key across /details/, /download/, /embed/, the metadata API and search; it is user-chosen, so formats vary (ia801… derivatives, bwb_…, twitch-511726326). Duplicate uploads of the same work are common: the sample had five near-identical cbfc-ecinepramaan-* certificates. Wayback keys are URL plus a 14-digit timestamp, with a content digest in CDX for dedup.

Retrieval unit

Item for catalogue search; page for books (FTS hits carry page_num); file for media. A TV item is one 30-minute broadcast, so segments inside it need ASR or the TV-news side index.

Cross-modal joins

Item identifier joins metadata, files and derivatives (stable). Open Library work/edition and OCLC IDs join books to external catalogues where present (text sample had both). Captions joined to video exist only where a caption file is in the file list; the sampled TV item had none.

Authoritative content field

For books, OCR text (_djvu.txt, Abbyy) is raw scan output; title and description are uploader-written and vary in quality. For TV, only title and runtime exist in the sample. SEO-style distortion is limited because item pages are not ranked on-site by keywords.

Freshness & recrawl

Catalogue grows about 47K items per day. Items rarely change after derivation, but lastmod in the sitemap moves with metadata edits (child entries span 2016 to 2026). Search counts update within hours of upload in the 7-day probe; deletion rate unmeasured.

Quality & spam

Trust varies by collection: curated collections (nasa, prelinger) versus bulk mirrors (github_narabot_mirror, pastpages, twitchstreams) versus open-upload opensource. Mass-ingested families dominate sitemap samples, so sampling by identifier prefix misrepresents the catalogue.

Internal vs external search

On-site search is the strongest path here: the same engine behind the UI is exposed as keyless APIs with counts, fields and a full-text backend. A third-party index duplicates less than on other sites and should lean on these APIs.

User query profile

Mixed: title and author lookups for books and media, exact-phrase research queries (the FTS endpoint returns page hits), and "does this URL exist in the past" lookups on Wayback.

Indexing Plan

  • Retrieval unit: item for metadata search, page for OCR'd books, 30-second chunks for media after ASR; one record per Wayback capture only for URLs a user asks about.
  • Primary keys & joins: identifier; Open Library and OCLC IDs for books; collection for provenance; Wayback URL plus timestamp.
  • Ingestion paths, ranked: 1) Scrape API with fields= in 10,000-row cursor pages: no key, covers all 129.6M items, about 13,000 calls for IDs alone. 2) Item metadata API for full fields and file lists: one call per item, no key. 3) Open files by /download/ with range reads: covers the roughly 70% not restricted. 4) Sitemap parts (78.1M URLs, 60% of items, apparently without web items) as a cross-check, not the primary path. 5) CDX for web captures, rate-limited.
  • Recrawl cadence: scrape the last seven days of addeddate daily; re-fetch metadata only when lastmod moves; Wayback lookups on demand.
  • Derivatives to generate: ASR on open movies/audio items without captions; OCR only where no DjVuTXT exists; thumbnails come free (__ia_thumb.jpg). Restricted items get metadata embeddings only.
  • Demo to build: a "restricted vs open" map: sample 1,000 identifiers by mediatype, HEAD their primary file, and show which parts of the catalogue an index can actually read.

Risks to the Index

  • Wayback wall hardening: the director's 2026-09-15 post says waves of high-volume automated traffic led to new 429 protections that sometimes block real users verified. A large CDX crawl may be refused.
  • The restricted layer can shrink or grow with lending and licensing decisions; a third of the catalogue is metadata-only today.
  • Terms of use were not read (the page is a JavaScript shell to curl); reuse limits for bulk mirroring are open.
  • News publishers are blocking Wayback crawlers, so new captures may thin out; see Nieman Lab, Jan 2026 verified (reported, not measured here).

  • Catalogue growth is steady near 47K items per day. Basis: 331,485 items with addeddate in one 7-day window; one window cannot show a trend.

Open Questions

  • What share of restricted items expose any anonymous file? HEAD the primary file of 1,000 identifiers stratified by mediatype and count 200s.
  • What rate trips a 429 on the metadata and Scrape APIs? Step request rate upward from 1 per second against the metadata endpoint, aborting at the first 429.
  • Which items are in the 40% missing from the sitemap? Page a random identifier slice through Scrape and test membership against the sitemap parts.
  • What do the terms of use allow for bulk reuse? Read the rendered /about/terms.php in a browser; curl returned a 2,138-byte script shell.
  • How many reviews and comments exist? Needs an authenticated call to /services/reviews.php or an item-count field in search.
  • How many items have caption or transcript files, especially in TV news? Search the file-format facet for SRT/VTT or sample file lists in tvnews.
