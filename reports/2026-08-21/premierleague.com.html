Context

The Premier League is a rights-selling cooperative owned by its 20 member clubs, which sell broadcast rights collectively and split the proceeds. premierleague.com services that business — a shop window and a fantasy game, not a destination monetised by page views. That shapes what an index builder finds. The site publishes almost no crawlable HTML: the homepage renders client-side and the sitemap lists landing pages, not content (Probe Log). Meanwhile the platform holding the data — an undocumented JSON API operated by Sony's Pulselive — answers without a key, without an Origin check and without a rate limit, and hands back Opta's own match and player identifiers in an altIds field. inferred The open API is an unguarded internal service, not a public offering. Basis: no documentation, versioning, auth or terms page of its own, while the site's terms forbid building a database from the same material (Sources).

Retrieval Notes (site-specific deltas)

Only where this site departs from the default platform assumptions.

Identifier & dedup

Four ID namespaces coexist and none is canonical. One player carried playerId: 740861, id: 19970 and altIds.opta: p232980 in a single record (Probe Log); FPL assigns a fifth. The Opta ID is the only one that means anything outside this site, and the site gives it away for free — unusual for a licensed feed.

Retrieval unit

The match, not the page. A completed fixture is a self-contained 29KB document with events, lineups and officials attached; the HTML page rendering it contains none of that text. Indexing pages here yields nothing — index the JSON.

Cross-modal joins

Editorial content is tagged with Opta team IDs (OptaID_t8 alongside club-produced-content:chelsea), so articles join to fixtures without any name matching. But two joins are unstable: altIds.opta was None on unplayed fixtures and populated only after the match, and FPL's pulse_id was 0 on all 380 fixtures pre-season. inferred Both keys are stamped by post-match reconciliation rather than at fixture creation. Basis: the completed fixture probed carried opta: g2562265 while every 2026/27 fixture carried none, on the same day.

Authoritative content field

Inverted relative to most sites: the API JSON is authoritative and the HTML is an empty shell. There is no SEO distortion to correct for because there is almost no SEO text.

Freshness & recrawl

Two regimes with no middle: an in-play match mutates every few seconds (clock, events, goals) for ~2 hours, then freezes permanently. Recrawling a settled fixture is pure waste — almost the entire corpus never changes again.

Quality & spam

No adversarial surface — no UGC, no ranking to game. The risk is duplication instead: 28 of 30 sampled "articles" were bodyless pointers to club sites, so an unfiltered ingest fills the index with headline stubs whose content lives on another domain.

Internal vs external search

The declared crawl surface cannot explain how this site is indexed at all: 865 sitemap URLs with no articles, and a homepage with two internal links. Whatever Google holds came from JS rendering or a surface not advertised in robots.txt — see Open Questions.

User query profile

Sharply time-boxed and answer-shaped: score, table position, fixture time, player stat, FPL price, spiking at kickoff and the weekly FPL deadline. Almost none are exploratory, so retrieval is judged on freshness and exactness, not ranking nuance.

Indexing Plan

  • Retrieval unit: the fixture document (match + events + lineups + officials), with player-season and team-season as secondary units and articles as a thin third.
  • Primary keys & joins: key on Opta IDs (g* match, p* player, t* team) because they survive outside this site; carry pulselive id and FPL element as aliases. Join editorial to entities via the OptaID_t* content tags, not by name.
  • Ingestion paths, ranked: 1) Football API — the whole structured corpus, ~136 pages at pageSize=100, no auth; the only path that scales. 2) FPL API — one 1.6MB call for the current-season player table plus 5 seasons of history. 3) Content API — editorial, capped at 30 items/page and mostly bodyless. 4) HTML crawl — worthless without JS execution, not worth the renderer budget.
  • Recrawl cadence: poll live fixtures every 30s during their ~2-hour window, sweep the current compSeason nightly, never re-fetch a settled season. Re-check altIds.opta and FPL pulse_id the morning after each match round, since both are stamped late.
  • Derivatives to generate: a natural-language summary per fixture (the API gives events but no prose), an Opta↔pulselive↔FPL concordance table, and embeddings for player name variants across the four namespaces. Skip ASR — no audio, and the sampled video was not closed-captioned.
  • Demo to build: a fixture-graph builder that sweeps one compSeason, resolves the three ID namespaces into one concordance, and reports which join keys were unpopulated at ingest — turning the pre-season pulse_id: 0 observation into a coverage number.

Risks to the Index

  • The terms forbid exactly what an index is. The Terms of Use permit downloading "for your own private and personal use" and then prohibit reproduction or redistribution, "including, by way of example, creating a database (electronic or otherwise) that includes material downloaded or otherwise obtained from the Website or App" (Terms of Use). Technical openness is not permission; the gap between them is the whole risk.
  • UK database right applies on top of copyright. The same terms assert "copyright, database rights and other intellectual property". Fixture lists and match data have been litigated in the EU/UK as protectable compilations, so a defence based on facts-are-not-copyrightable is weaker here than in a US-only analysis.
  • The data is Opta's, sub-licensed. Ground records are stamped "source":"OPTA" and Opta IDs ride in altIds (Probe Log). Reuse rights sit with Stats Perform as much as the League, so a licence from the League alone may not cover the payload.
  • inferred The open API can close without notice. Basis: no documentation, no version prefix, no auth and no deprecation policy, and pageSize=1000 already fails with a 504 — nothing in it is contractual.
  • Platform consolidation is live. Pulselive, which operates the API, is being folded into Sony sister company Beyond Sports and its brand retired (Pulselive) — the most likely trigger for endpoint churn.
  • No robots-level AI signal to rely on. robots.txt names no AI crawler and blocks no path (Probe Log). That is an absence of a stated position, not consent, and such gaps get filled with restrictive rules rather than permissive ones.

Inferences

  • The football API is an unguarded internal service, not a public product. Basis: no documentation, no version prefix, no auth, no Origin enforcement and no terms of its own, while the site's Terms of Use forbid building a database from the same material.
  • Opta match and player IDs are stamped by post-match reconciliation, not at fixture creation. Basis: on 2026-08-21 a completed fixture carried altIds.opta: g2562265 while all 380 unplayed 2026/27 fixtures carried none, and FPL's pulse_id was 0 on every one of them.
  • OptaID_t8 denotes Chelsea. Basis: it co-occurred with the club-produced-content:chelsea tag on the same content objects in the 30-item sample.
  • The 30-second CDN max-age is sized for the live-match window, not editorial. Basis: settled fixtures are immutable in the API, so nothing but in-play state justifies a 30-second TTL on a 35-season archive.
