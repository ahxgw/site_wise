Context

ThePornDude hosts no pornography. It is a persona-branded directory ("The Porn Dude", a cartoon mascot) that ranks and reviews other adult destinations: tubes, premium studios, cams, AI generators, and, increasingly, individual creator accounts on OnlyFans, Fansly, Reddit and Twitter. Each listing is a ~1,500-word first-person review with pros/cons, screenshot thumbnails, and a "visit" button. The current registration dates from November 2013, and the About page says "since 2013". The operating entity is undisclosed: WHOIS sits behind a privacy proxy and the Terms name only Slovenian governing law, which "does not imply" operating there. The About page promises "No Adverts, Ever!". Terms §14 says the site "receives compensation" for some placements, and the visit buttons resolve to affiliate-tagged URLs. For a full-modal index it matters as an editorial graph source. Its text is thin SEO prose, but its curated, categorised outbound links map a whole vertical that the tubes themselves never cross-link.

Retrieval Notes (site-specific deltas)

Only where theporndude.com differs from the default platform assumptions.

The asset is the edges, not the nodes

Most sites are indexed for their objects. Here the review text is templated first-person filler, and the valuable record is listing ID → outbound domain → category. Index the listing as an entity that resolves to a third-party site. Each review then becomes a typed, categorised pointer into the adult vertical, which is a strong seed list for crawling the destinations.

Identifier & dedup

The numeric ID is the only stable key: any slug, or none, 301s to canonical. Locale is a namespace, not just a translation. 3,751 IDs exist only under /zh/, /ja/ and the like and 404 at root, so a root-only crawl silently drops 23% of the corpus. Join locale variants on ID; treat porndudedeutsch.com as the de namespace of the same ID space.

Outbound URL canonicalisation

Visit links come in three shapes: direct, first-party redirector (pdude.link/{slug}), and affiliate-tagged destination (?ref=, sjv.io, t.anexo.link). Resolve redirects once, then strip tracking parameters down to the registrable domain. The redirector slug equals the review slug, so the mapping is cheap to rebuild.

Structured data lies

The JSON-LD aggregateRating is one constant (3.82 / 15,514) stamped on every review. It is rich-result bait, not data. og:updated_time is render time and blog lastmod is bulk-rewritten (a 2020 post reads 2026-10-01). Trust only Product.name, the editor reviewRating, and the pros/cons list.

Freshness has no signal

Sitemaps omit lastmod and shuffle IDs, so new listings can't be found by diffing file tails. Because IDs are monotonic, track the max ID across all locale namespaces instead; any ID above the last high-water mark is new.

Quality & trust tier

Ranking position is commercially influenced: Terms §14 admits compensation, and a fifth of homepage slots route through affiliate redirectors. Use the placements as coverage (this site exists, in this category) and never as a quality vote. The 185 nofollow slots are a weak paid-placement hint worth keeping as a feature.

Access posture

The inverse of the default "curated SEO sliver". There is no allowlist, no AI-agent policy, and no account wall, just a Cloudflare rule that challenges non-browser UAs on HTML while leaving the CDN open. A declared crawler UA will be challenged like plain curl; get operator allowlisting rather than spoofing a browser string.

Indexing Plan

How Site Wise would build the index for this site.

  • Retrieval unit: the listing, keyed by numeric ID, carrying name, category set, canonical outbound domain, editor rating, pros/cons, review text, and a thumbnail URL. Categories are a second unit keyed by slug.
  • Primary keys & joins: listing ID ↔ locale path ↔ redirector slug ↔ outbound registrable domain. The outbound domain is the join into other Site Wise reports (xvideos.com, pornhub.com, eporner.com are all listed).
  • Ingestion paths, ranked: 1) sitemap census of both domains (31 requests), ceiling = 16,271 + German IDs; 2) one homepage + 152 category-page fetches for placements and categories; 3) per-ID review fetch at ≤1 req/s for text and visit links (~16K requests); 4) one redirector resolution per distinct slug, then cache it; 5) blog RSS for the 844-post side corpus. No API, dump, or feed exists for reviews.
  • Recrawl cadence: daily high-water-mark probe on new IDs; homepage and category placements weekly; review bodies quarterly; redirector targets monthly, since affiliate programs rotate.
  • Derivatives to generate: outbound-domain graph with category labels; text embeddings of pros/cons only (the long prose is low-signal); skip OCR, because thumbnails are censored screenshots, and skip ASR (no media).
  • Demo to build: resolve every visit link once and measure the affiliate share by category. That turns "directory" vs "affiliate funnel" from a claim into a number, and yields a clean, deduped seed list of adult destinations for the wider crawl.

Risks to the Index

Only risks that change indexing strategy.

  • Domain instability is designed in. The homepage advertises fallback domains "in case ThePornDude has been banned in your country", and German already lives on its own domain. Key the index on listing ID plus persona, not hostname, so a domain move re-points rather than forks the corpus.
  • Gate hardening. The current gate is a UA rule. Escalating to a JS challenge for browser UAs (the Epic Games pattern) would close HTML entirely, leaving only the unchallenged CDN. Capture the ID → domain graph early; it is the part that can't be rebuilt from the CDN.
  • Commercial bias contaminates labels. If placements feed a quality model downstream, paid ranking leaks in. Keep directory membership as a boolean coverage signal, never as a rank feature.
  • Age-verification and listing-liability laws. The 2257 page and Terms §5 shift compliance onto listed sites. Regimes that treat directories as facilitators (UK, US states) could force geo-blocks; the ipinfo.be preload shows country-aware serving is already wired in.
