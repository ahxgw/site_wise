sssinstagram.com

sssinstagram.com is a 263-page Instagram downloader, a twin of fastdl.app, that shows its sitemap only to named crawler user agents.

Context

sssInstagram turns a pasted Instagram link (post, reel, story, highlight, profile) into a downloadable file. Like yesterday's fastdl.app it owns no media: 263 sitemap pages, all tool landing pages in 29 locales. The two hosts run the same code. Both use a workerHubDomain resolver that answers in SaveFrom's sf.result namespace, both sell the same Instagram MCP at the same prices, and both MCPs authenticate against the same OAuth server on multitool.cloud. The domain is older (registered 2018), and its traffic mix leans Latin American where fastdl's leans South Asian. Two things are new for an index builder. First, the site serves its sitemap and its API page only to user agents it recognises as search or AI crawlers. Second, it publishes an llms.txt that pitches the scraping MCP to AI assistants by name.

Retrieval Notes (site-specific deltas)

Deltas from the default assumptions and from the fastdl.app baseline. Its resolver, MCP and ad stack are not repeated here.

Crawl access by UA name

The sitemap and the /api page are served only to user agents named Googlebot, bingbot, YandexBot, GPTBot or ClaudeBot. Everyone else, real Chrome included, gets a noindex "permanently unavailable" page. There is no reverse-DNS check, so the gate stops only honest crawlers that send their own UA. A new crawler should neither spoof a UA nor trust the gate's verdict. It should rebuild the URL set from the hreflang cluster on /en1, which gives 29 locales × 9 page types.

Identifier & dedup

The URL scheme is less unstable than fastdl's: locales use plain codes (/de), and only English carries a digit slug (/en1, which absorbs /en, /en0, /en2). English is split between /en1/… and unprefixed paths, while the JSON-LD SearchAction still points at /en. Key pages on (function, locale), as for fastdl.

Cross-site dedup

This host and fastdl.app serve the same product. FAQ and HowTo text differ, but the MCP page, tool list, prices and OAuth server are the same. An index should attach both to one operator entity and treat their /mcp pages as duplicates of one offering.

Agent-facing surface

llms.txt is new for this network. It is written for AI assistants, and its "typical uses" (influencer research, audience comparison, follower lists) describe surveillance of third-party accounts. An LLM-oriented crawler that ingests llms.txt files as trusted site summaries will pick up an ad for a scraping service. Treat llms.txt as marketing copy, not ground truth.

Freshness & recrawl

Unlike fastdl, lastmod exists and moves: 10 distinct dates in 2 months. A weekly fetch of the sitemap with a named-crawler UA (where policy allows) or of the hreflang set gives cheap change detection.

User query profile

The estimators disagree on the audience. Similarweb ranks it Latin American and Spanish-led with 41% direct traffic; Ahrefs search data leads with India and Indonesia (Verified Metrics). A 2018 domain with large direct traffic suggests a bookmarked brand rather than a search landing. Country weighting stays open.

Indexing Plan

  • Retrieval unit: the tool page (function × locale), 261 documents, plus /api and /mcp as "data service" units shared with fastdl.app.
  • Primary keys & joins: sssinstagram:{function}:{locale}; operator entity = the multitool.cloud network (fastdl.app, sssinstagram.com). Drop all query-string variants.
  • Ingestion paths, ranked: 1) hreflang expansion from /en1 (~263 fetches, no UA games). 2) llms.txt as a link list, labelled as marketing. 3) Nothing else: the resolver is signed and the MCP is unlicensed resale.
  • Recrawl cadence: weekly hreflang/home hash; monthly /.well-known/oauth-protected-resource check to track which hosts share the auth server.
  • Derivatives to generate: a "UA-gated resource" flag. For every host, fetch robots.txt's sitemap with an honest UA and with a crawler UA. Where the responses differ, record it as cloaking evidence; do not ingest the crawler-only view.
  • Demo to build: an MCP auth-server graph. For each candidate downloader host, POST to its advertised MCP URL, follow resource_metadata, and group hosts by authorization server. Two hosts already share auth-gate.multitool.cloud. One cheap request per host maps the operator network more reliably than bundle markers.

Risks to the Index

  • Crawler-specific content. The site serves named crawlers resources that humans cannot fetch (Probe Log). Today the gated items are the sitemap and an API sales page. The same mechanism could serve crawlers different page bodies, so a crawler that spoofs a UA learns nothing about what users see.
  • Prompt-surface pollution. llms.txt pitches a scraping MCP to AI assistants by name. Agent-tool registries and LLM crawlers that trust llms.txt would spread the pitch.
  • inferred sssinstagram.com and fastdl.app have one operator. Basis: both MCP endpoints return resource metadata naming auth-gate.multitool.cloud/mcp/oidc, both /api/convert resolvers answer with sf.result, and the MCP tiers and the 12-tool list match (Probe Log; fastdl.app report). Removing either host would not shrink the offering.
  • inferred The UA gate exists to keep the URL inventory and the API sales page away from ordinary visitors and competitors while keeping them crawlable. Basis: of the first-party pages tested, only /api and the sitemap are gated, and both still return 200 to the named search and AI crawlers (Probe Log). The newer /mcp page is not gated, so the gate is not applied consistently.
